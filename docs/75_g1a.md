# 75. G-1a — 앱보다 빠른가: 저장 자료는 우리 쪽만 재고, 앱 쪽은 못 잰다

작성: 2026-08-27 · 소유: W1 · **라이브 API 호출 0**

## 0. 결론 — **(라) 못 갈랐다**

저장 자료만으로는 **앱이 우리와 같은 랭킹 개정본을 같은 나이에 보는지** 가를 수 없다.
자료가 재는 것은 우리 쪽뿐이다.

- 2026-08-18 정규장 보존 JSON에서 `TOSS_SECURITIES_TRADING_VOLUME / realtime` 응답의
  `sent_epoch - rankedAt`은 1초 팔 p50 **16.795초**, 5초 팔 **18.0초**, 12초 팔
  **18.1초**다.
- 같은 자료의 미수신율은 1초/5초/12초 팔에서 **33.3% / 32.8% / 33.9%**다.
  1초 팔의 `rankedAt` 초 자리는 `:09 :19 :39 :49` 네 개뿐이고, `:29 :59`는 없다.
  따라서 그 창의 33%는 우리 폴 주기가 놓친 칸이 아니라 **우리 API 응답 경로가 내지 않은
  고정 두 칸**이다.
- 2026-08-24~26 세 정규장의 현재 DB도 랭킹 내용 변경이 **4.054~4.092회/분**이다.
  현재 로그의 `config_sig`는 여전히 `rk12s`이고 실제 스냅 간격 p50은
  **12.546~12.548초**다.
- 그러나 현재 DB는 `rankedAt`을 저장하지 않고, 운영 로그에도 그 값이 없다. 앱 쪽에는
  응답 본문·헤더·화면 시각 어느 것도 저장돼 있지 않다. 앱이 약 10초마다 한 번에 바뀐다는
  사용자 관찰은 **주기**를 말할 뿐 **개정본의 나이**를 말하지 않는다.

그러므로 *"앱도 같은 서버 값을 받는다면 우리와 같은 나이다"*라는 **조건문은 맞지만,
그 전건이 측정되지 않았다.** 이 문서의 결론은 (라)다. G-1a 통과 여부는 이 결론과 별개인
사용자 판단이며 `USER-INPUT-QUEUE` D-26 (다)에 남긴다.

그리고 이 문서는 **인지**만 답한다. 인지 뒤 실제 주문이 남들보다 먼저 체결되는지라는
**집행**은 실주문이 필요한 D-2다. 여기서 집행까지 답했다고 읽으면 안 된다.

## 1. 질문을 두 번 나눈다

*"인간보다 빠른가"*에는 적어도 두 질문이 있다.

| 층위 | 질문 | 이 문서 |
|---|---|---|
| 인지 | 랭킹 개정본을 앱 사용자와 같은 시점에 아는가 | **대상** |
| 집행 | 안 뒤 주문을 보내 남들보다 먼저 체결되는가 | **대상 밖 — D-2** |

인지 안에서도 둘을 섞으면 안 된다.

1. **우리 쪽 나이**: 우리 응답의 `rankedAt`과 수신 시각 차이는 얼마인가.
2. **앱과의 상대 나이**: 앱이 같은 `rankedAt` 개정본을 언제 처음 화면에 내는가.

1번은 저장 자료로 재현된다. 2번은 앱의 개정본과 최초 표시 시각이 없어서 재현되지 않는다.
서버가 오래 들고 있던 시간이 크다는 사실은 2번을 자동으로 답하지 않는다.

### 3-2. 세 팔 요약

### 4-1. 보존 원자료가 확정하는 것

같은 정의로 다시 센 결과다.

| 팔 | 슬롯 | 미수신 | 미수신율 | `rankedAt` 델타 |
|---|---:|---:|---:|---|
| 1초 | 18 | 6 | **33.3%** | `+10` 6, `+20` 6, `+30` 0 |
| 5초 | 119 | 39 | **32.8%** | `+10` 41, `+20` 39, `+30` 0 |
| 12초 | 118 | 40 | **33.9%** | `+10` 39, `+20` 38, `+30` 1 |

1초 응답열을 stride 1·2·4·5·8로 다시 읽어도 슬롯 18, 미수신 6, 33.3%가 그대로다.
1초 팔의 고유 `rankedAt` 13개는 모두 `.000`이고 초 자리는 다음 네 개뿐이다.

나머지 두 칸은 생기지 않았다. **우리 폴 누락은 아니다.** 다만 이 자료 하나로
*원 서버가 만들지 않았는지 / 우리가 붙은 캐시 경로가 내지 않았는지 / 앱 경로도 같은지*는
가르지 못한다. 이 경계가 앱 비교에서 중요하다.

## 5. 앱과의 비교가 왜 저장 자료로는 안 되는가

저장 자료에 있는 앱 쪽 사실은 사용자의 한 관찰뿐이다.

> 앱의 급상승 랭킹은 약 10초 멈췄다가 한 번에 바뀐다.

이 관찰은 앱 화면의 **갱신 주기**가 서버 격자와 어울린다는 증거다. 다음은 아니다.

- 앱 화면이 `TOSS_SECURITIES_TRADING_VOLUME / realtime`인지,
  `TOP_GAINERS / 1d`인지에 대한 1:1 매핑
- 앱이 받은 개정본의 `rankedAt`
- 같은 개정본이 앱에 처음 그려진 시각
- 앱 경로와 Open API 경로가 같은 캐시 개정본을 내는지
- 앱이 `:29 :59` 개정본도 보는지

같은 개정본 `r`이 양쪽에서 식별되면 비교식은 단순하다.

```text
age_us(r)  = first_seen_us(r)  - rankedAt(r)
age_app(r) = first_seen_app(r) - rankedAt(r)
delta(r)   = age_us(r) - age_app(r)
           = first_seen_us(r) - first_seen_app(r)
```

같은 `rankedAt(r)`은 차분에서 소거된다. 그래서 **같은 개정본과 양쪽 최초 관측 시각**만
있으면 앱이 `rankedAt`을 화면에 쓰지 않아도 비교할 수 있다. 지금은 그 둘이 없다.
주기가 비슷하다는 사실로 같은 개정본·같은 나이를 대신하면 순환논증이다.

## 6. 프로브 설계 — **이 과제에서는 쏘지 않았다**

목적은 앱과 현재 수집기가 같은 랭킹 개정본을 언제 처음 보는지 짝지어 재는 것이다.
수집기·config·천장·워치독은 바꾸지 않는다.

### 6-1. 먼저 화면과 API 셀을 고정한다

1. 앱 화면 이름, 시장, 세션, 정렬 기준, 보이는 상위 N개를 기록한다.
2. 대응 API의 `type / duration / marketCountry / count`를 **데이터를 보기 전에** 하나로
   고정한다. *급상승*이라는 이름만 보고 `TOP_GAINERS / 1d`라고 추측하지 않는다.
3. 앱의 상위 N개 순서와 API의 상위 N개 순서가 같은 개정본으로 반복 매칭되지 않으면
   **다른 피드**로 중단한다. 그 경우 결론은 계속 (라)다.

### 6-2. 동시에 남길 세 시계

| 시계 | 남길 것 |
|---|---|
| 기준 API | 단조 `send/receive`, 서버 `Date`, `rankedAt`, 상태, 요청 ID, limit/remaining/reset, 상위 N `order`와 랭킹 값 해시 |
| 현재 수집기 | 읽기 전용 DB에서 `snap_ms`와 같은 상위 N 내용 해시. 현재 `rk12s` 그대로 |
| 앱 | 앱 화면과 **같은 프레임 안의 호스트 시간코드**를 60fps로 촬영. 손 반응이 아니라 실제 화면 변경 프레임을 읽음 |

앱은 `lastPrice`·`changeRate`처럼 초 단위로 따로 도는 값을 매칭 키로 쓰지 않는다.
순서와 화면에 보이는 랭킹 값을 사용하고, 앞뒤 개정본과 구별되지 않는 해시는 버린다.
영상 지연은 관측 전·후 시간 플래시로 보정하며, 결과를 보기 전에 두 보정 중 큰 오차와
한 프레임을 더한 값을 계기 오차 `epsilon`으로 고정한다.

### 6-3. 발사안과 중단선

- 서로 다른 정규장 두 창, 각 **5분**
- 기준 API **1초 간격**, 계획 600콜, 절대 상한 **620콜**
- 토큰은 수집기 소유 상태를 읽기만 하고 발급·갱신·무효화하지 않는다
- 첫 429, 인증 이상, 수집기 정지, 기준 팔 마감 누락, 앱 화면 이탈 때 즉시 중단
- 총 고유 매칭 개정본 **30개 미만**이면 속도를 추정하지 않고 표본 부족으로 (라)

이 숫자는 설계안일 뿐 승인이나 발사가 아니다. 라이브 API를 쓰므로 별도 사용자 결정 뒤에만
실행한다.

### 6-4. 미리 정할 출력

개정본마다 `age_us`, `age_app`, `delta`, 매칭 여부를 내고, 양쪽 미관측률도 따로 센다.
1차 통계량은 짝지은 `delta`의 중앙값이다. 95% 구간은 세션 안의 연속 60초 블록을
10,000번 재추출하는 이동 블록 부트스트랩으로 만들고, 세션별 중앙값도 함께 낸다.
계기 오차 `epsilon`을 고정한 뒤 다음 네 칸만 쓴다. 방향 판정은 두 세션의 중앙값 부호도
같아야 하며, 다르면 (라)다.

| 출력 | 규칙 |
|---|---|
| 인지에서 앱과 동률 | 짝지은 `delta`의 95% 구간이 `[-epsilon, +epsilon]` 안 |
| 앱보다 느림 | 그 구간의 하한이 `+epsilon`보다 큼 |
| 앱보다 빠름 | 그 구간의 상한이 `-epsilon`보다 작음 |
| 못 가름 | 피드 매핑 실패, 매칭 30개 미만, 또는 구간이 경계를 걸침 |

앱과 동률이 나와도 *"인간보다 빠르다"*가 아니다. 그때 전략 문장의 의미는
**인지 우위가 아니라 D-2의 집행 우위만 남는다**로 바뀐다.
