## 1. 무엇을 노리는가

**정본은 사용자 문장이다** (`coordination/USER-INPUT-QUEUE.md` D-6, 2026-08-04):

> **"토스 커뮤니티/급상승 랭킹으로 인해 작전/동전/급등주로의 개미 유동성 몰림이 매일
> 발생하고, 우리는 스크립트 레벨에서 인간보다 빠르게 행동해 그 유동성을 발라먹는다."**

**이 문장은 두 번 고쳐진 것이다.** 옛 판을 인용하지 않도록 세대를 적어 둔다:

| 세대 | 언제 | 무엇이었나 | 왜 바뀌었나 |
|---|---|---|---|
| 1 | 2026-07-30 | *"급등 **전조**를 미리 찾아 감시한다"* | 사전 매집은 드물고(La Morgia: 104 건 중 4 건) 정보 대부분이 시작 직후 수 초에 있다 |
| 2 | 2026-08-02 | *"러너들 **사이를 옮겨다니는** 유동성을 스크립트 레이턴시로 얇게 발라먹는다"* (`docs/16`) | 사용자 확정. **전조 탐지는 사이드 알파로 강등** |
| **3** | **2026-08-04** | 위 + *"1 분봉 해상도가 틀렸다 → 고해상도로 재시작"* | 후보 5 개가 전부 죽은 원인이 해상도라고 사용자가 판단 (D-6) |

**전략 방향의 정본은 `docs/16_strategy_design_notes.md`,** 착수 관문은 `docs/58_gate.md`,

### 조사가 이 가설에 무엇을 보탰나 (`docs/02_theory_background.md`)

1. **메커니즘은 학술적으로 실증돼 있다.** Barber et al. (2022, *Journal of Finance*)
   로빈후드 연구: 앱의 Top Mover 리스트가 **인과적으로** herding 을 만들고, herding 된
   종목은 이후 20 일간 평균 **−4.7%** 비정상수익률. 토스 급상승 리스트는 같은 기계다.
   → **어텐션 피크는 매수 신호가 아니라 청산 카운트다운이다.**
2. **"조용한 매집을 미리 찾는다"에는 한계가 있다.** La Morgia et al. (2020): 104 건 중
   **4 건**에서만 사전 매집이 관찰됐고, 정보 대부분은 **시작 직후 수 초의 체결 버스트**에
   있었다. 합성데이터 실험도 재현했다 — 즉발형은 T0 이전 RVOL 이 1.2(완전 정상)라
   **원리상 전조 탐지가 불가능**하다. → 검출기를 **전조 경로 + 확인 경로 2 개**로 나눈 이유.
3. **미국판 '주포 덤프'는 희석(dilution)이다.** 고점 오퍼링(424B5), 공지 없는 ATM 드립,
   toxic 워런트. 그리고 **하방 LULD 홀트 중에는 손절 주문이 체결되지 않는다.**
   미국은 하한가가 없어 하루 −85% 도 난다.
4. **기저율이 보수적 운영을 강제한다** (SmallCapLab, 900+ 거래일): 프리마켓 대량거래
   갭퍼의 **71.5% 가 페이드**, 고점의 **63% 가 10:00 ET(≈한국 자정) 전** 형성,
   **73% 가 VWAP 아래 마감**.
5. **비용**: 토스 US 수수료 0.1%/체결 → 왕복 0.2% + 환전 스프레드 + 슬리피지.
   **양도세 22%(연 250 만원 초과분), 손실 이월공제 없음** — 이긴 해 과세/진 해 이월 불가의
   비대칭. → 신호는 조밀하게, **거래는 고확신 이벤트로 압축**해야 복리가 산다.

## 2. 토스 Open API 실측 사실

> **정본은 `docs/06_live_facts.md`(W1) 다.** 여기 있는 것은 **설계를 바꾼 것만** 추린
> 것이고, 둘이 다르면 **06 이 이긴다.** 스펙 자체는 `docs/01_api_analysis.md`.

### 2-1. 구조적 제약

| 항목 | 사실 |
|---|---|
| 프로토콜 | **REST 전용. 웹소켓 없음** → 모든 감시는 폴링 |
| 인증 | OAuth2 client credentials. **client 당 유효 토큰 1 개** — 재발급 시 기존 토큰 즉시 무효 |
| IP | 화이트리스트 필수 (미등록 시 403) |
| Rate limit | 그룹별 req/s: MARKET_DATA 10, CHART 5, RANKING 5, STOCK 5, MARKET_INFO 3, AUTH 5 |
| 샌드박스 | 없음 |

> **토큰 1 개 제약이 아키텍처를 지배한다.** 두 프로세스가 각자 토큰을 발급하면 서로를
> 죽인다. `TokenManager` 가 OS 파일락 + 상태파일로 단일성을 강제하지만 **같은 머신·같은
> 상태파일 경로**가 전제다. 경로가 갈리면 락이 무의미해진다.

> **★ 서버 한도가 움직였다 (2026-08-11~13).** 서버가 MARKET_DATA 를 **20/s** 로,
> CHART 를 **20/s** 로 광고하는데 우리 클램프가 각각 10·5 로 잘랐다. **클램프 규칙 자체는
> 옳다**(감사 B-2: 초당→분당 의미 변화 시 rate 60 배 점프를 막는다) — 결함은 **잘랐다는
> 사실이 어느 줄에도 안 남았던 것**이다(`docs/56`). **20/s 가 진짜 사양 상향인지 헤더
> 의미 변경인지는 아직 모른다.** 모르면 천장을 못 올린다.

### 2-2. 시세 데이터의 실제 거동 (설계를 바꾼 발견들)

1. **1 분봉이 최소 1024 일(≈2.8 년) 보관된다.** → *"지금부터 쌓아야 한다"* 는 전제가
   무효. **과거 백필로 즉시 분석 가능.** 단 소형주는 365 일까지만 확인됐고,
   CRKN 처럼 **일봉 이력이 41 봉뿐인 종목도 있다.**
2. **미국 `/orderbook` 은 최우선 1 레벨만 준다.** depth 파라미터 없음.
   → 호가창 깊이·다단 불균형 지표는 **존재할 수 없다.** 테이프 중심으로 재설계.
3. **소형주는 체결이 없으면 `/prices.timestamp` 가 null 이거나 과거에 고정된다.**
   같은 배치에서 AAPL 은 실시간인데 SNTI·CRKN 은 null, BTAI 는 74 분 고정.
   **`lastPrice` 는 계속 온다 — 이 값을 "현재가" 로 신뢰하면 안 된다.**
   → 오히려 더 나은 신호를 발견: **`first_print`(null→값 전이)와 `staleness` 급감 =
   "휴면 동전주가 깨어나는 순간"**. Tier 1 승격 트리거 1 순위로 올렸다.
4. **`/trades` 는 최대 50 건** → 활발한 러너의 테이프는 **전량이 아니라 표본**이다.
   그 상한이 바쁠 때 실제로 물린다는 것을 `docs/41` §4 가 찾았고 `docs/43` 이 계측화했다.
5. **`adjusted=true`(수정주가)는 임의 정밀도를 만든다.** CRKN 2025-03-05:
   adjusted `0.10461614`(8 자리) vs raw `1.9889`(4 자리). → 계약 A4·A5 의 원인(§4).
6. **`TOP_GAINERS`/`TOP_LOSERS` 는 realtime 미지원**(400). **단 `1d` 는 200 이고 갱신
   속도도 거래량 랭킹과 비슷하다**(4.77 vs 4.51 회/분) — 그래서 실제로 수집 중이다.
7. **랭킹 스냅샷은 과거 조회가 불가능하다.** 실시간 수집으로만 얻는다 —
   **수집하지 않은 시간은 영구히 사라진다.**
8. **★ 서버는 거래량 랭킹을 10 초 벽시계 격자에서 재계산한다** (`docs/35`, W1 실측).
   재계산의 **약 30% 는 우리에게 안 온다**. 받아든 것은 **중앙 16~18 초 늙어 있다.**
   → 이것이 지금 `docs/58_gate.md` 의 **1 번 관문**이다.
   > ★ **정정 (2026-08-20).** 이 줄은 원래 ~~*"우리 폴 주기가 12.4 초라 재계산의 29% 를
   > 못 받고"*~~ 였다. **폴 주기 탓이 아니다.** 29.4% 는 애초에 **1 초 팔**에서 나온 값이고
   > (`docs/35` §0-1·§7-0), 2026-08-18 프로브가 정규장에서 **1 초 / 5 초 / 12 초**를 나란히
   > 재보니 미수신율이 **33.3% / 32.8% / 33.9%** 로 **셋이 같았다**(`docs/35` §7-2).
   > 노후도 **16.8 / 18.0 / 18.1 초**다. **빠지는 것은 우리가 놓친 것이 아니라 서버가
   > 자기 격자를 건너뛰는 것**이고, 남은 지연의 대부분은 서버가 들고 있던 시간이다.
   > 이 오인은 코디네이터가 W1 명세에 써 넣은 것이고 W1 이 잡았다.

### 2-3. 함정 목록 (하나라도 놓치면 데이터가 조용히 틀어진다)

| # | 함정 | 대응 |

| 1 | 미존재 심볼은 404 가 아니라 **200 + 응답에서 조용히 누락** | 요청/응답 심볼 대조 |

### 3-1. 티어드 감시 구조

```
Tier 0  유니버스 (수천, 일 1회)   외부 심볼 디렉토리 + 랭킹 출현 종목 누적
Tier 1  광역 워치 (~1500)        /prices 배치 200개 스윕 45s
Tier 2  활성 워치 (~300)         /candles 1m 110s
Tier 3  집중 감시 (20)           /trades 4s + /orderbook 16s
랭킹    별도 예산                거래량 2종 + TOP_GAINERS(1d)
```

**예산 산식** — 한도 × usage_ratio 0.7:

```
MARKET_DATA (10 × 0.7 = 7.0):
  tier1 1500/200/45s = 0.17 + tier3 20/4s = 5.00 + tier3 20/16s = 1.25  →  6.42  ✅
MARKET_DATA_CHART (5 × 0.7 = 3.5):
  tier2 300/110s = 2.73  →  여유 0.77(22%)   ※ 이 여유는 승격 직후 백필용이다
```

> tier3_max=30 이면 9.54 로 **예산 초과**. tier2 를 90s 로 하면 여유가 4.8% 뿐이라
> 백필이 겹칠 때마다 가드가 tier2 를 줄여 **커버리지가 조용히 무너진다.**
> 두 값 다 실측으로 정한 것이다.

### 3-2. 검출기의 이중 경로

```
precursor_score(feats)   T0 이전 축적: RVOL 궤적·토스 쏠림도·coil·휴면→각성
                         → 리드타임이 있지만 즉발형은 놓친다
confirm_score(feats)     T0 봉 자체의 폭발: 봉 거래량 z, 5분 수익률, coil 급반전
                         → 리드타임 없지만 "시작 후 수 분 내 확인-진입" 가능
```

- 둘 중 큰 쪽으로 승격하되 **승격 사유에 어느 경로였는지 기록**한다 →
  `promotions` 테이블이 **두 경로의 리드타임·적중률을 따로 평가**할 수 있다.
- 모든 피처는 **버킷/램프로 [0,1] 정규화** 후 가중합. 분모가 작아 100 배를 넘길 수 있는
  값은 절대 스케일로 쓰지 않는다.
- **`coil_score` 는 부호가 반직관적**: 양수 = 변동성 수축 진행(전조),
  **강한 음수 = 방금 폭발 시작**(확인).
- **NaN 피처는 0 점.** 데이터가 없을수록 점수가 낮아야 승격이 보수적으로 일어난다.

## 4. 계약 개정이 왜 그렇게 정해졌나

**정본은 `docs/04_contracts.md`.** 여기는 **이유만** 남긴다.

| ID | 내용 |
|---|---|
| C-1 | 모든 시간은 **UTC epoch ms 정수**. 세션은 API 캘린더로만 판정 |
| C-2 | 가격·금액 = **마이크로달러 int**, 수량 = 마이크로주 int. **float 금지** |
| C-5 | 에러별 재시도 책임 위치 고정 |
| C-6 | SQLite WAL, **쓰기는 collector 단일 프로세스**, 분석기는 read-only |
| C-9 | `TOSS_BASE_URL` 로 mock 전환. **리스 없는 워커는 mock 만** |
| C-11 | **주문/조건주문/계좌변경 금지** — 래퍼조차 만들지 않고 HTTP 레벨 이중 차단 |

**개정 (전부 실측·실험에서 나왔다)**

- **A1 (분석 해석)**: 룩어헤드 컷오프를 엄격히 하되 **`include_t0` 플래그**를 제공.
  실시간 검출기는 T0 봉 종료 시점에 판정하므로 T0 봉을 정당하게 볼 수 있다.
  **RVOL 게이트 미적용 이벤트는 통계에서 분리**해야 한다(조용한 오염 방지).
- **A2 (라이브 실측 반영)**: 호가 1 레벨 확정 → 테이프 중심 재배분. 소형주 timestamp
  null → **`first_print` 를 Tier 1 승격 1 순위**로. 1 분봉 1024 일 보관 → 백필 분석과
  실시간 수집 병행. **후속 개정으로 컷오프가 `ts_ms <= t0_ms`(봉) / `snap_ms < t0_ms`
  (스냅) 비대칭**이 됐다 — 봉은 구간이고 스냅은 순간이기 때문이다(`docs/48`·`49`).
- **A3 (호가 불균형)**: 계약은 비율형 `[0,1]`, 코드는 부호형 `[-1,1]` 이었다. 중립점이
  달라(0.5 vs 0) 소비자가 조용히 틀린다. **부호형을 정본으로 하고 컬럼명을
  `imbalance_signed` 로 변경** — **이름이 규약을 말하게 했다.**
- **A4 (정밀도)** ★: `dec_to_u` 가 1e-6 초과 정밀도를 `SchemaMismatch` 로 거부 →
  **심볼 스킵**. 그런데 스킵되는 게 하필 **표적 종목군(저가 동전주)** 이었다.
  → **반올림(ROUND_HALF_EVEN) + 반올림 카운터 노출.** 나노달러로 안 바꾼 이유:
  가격×수량 누적이 int64 를 1000 배 빨리 넘긴다.
  실측: 라이브 **17,179 건 중 13 건 반올림** — 예전 코드였다면 13 건이 전부 스킵.
- **A5 (수정주가)** ★: 수정주가는 **그 시점의 명목 가격을 지운다.** CRKN 은 실제로
  $1.99 에 거래됐는데 수정주가로는 $0.10 로 보인다 → **당시 $2 종목을 동전주로 오분류.**
  게다가 sub-penny 호가·LULD 밴드 경계($0.75/$3)가 전부 명목가 기준이다.
  → **1 분봉은 원주가, 일봉은 수정주가.** 분할은 장중에 없으므로 일중 상대 변화는
  원주가로도 동일 — **잃는 게 없다.**
- **A6 · A7**: 토큰 리스 자격증명 단위 · `ForbiddenEndpoint` 상속 분리 · CAS invalidate ·
  KR 제거 · 상태파일 권한. **Windows 의 `os.chmod` 는 읽기전용 비트만 만지고 ACL 에는
  영향이 없다** — `icacls /inheritance:r` 로 분기했다. `os.chmod` 만 썼으면
  *"권한을 걸었다"* 고 믿으며 실제로는 아무 보호가 없었을 것이다.

## 6. Phase 2(실매매) 설계 시 지켜야 할 것

> 착수 관문은 `docs/58_gate.md` 다. 아래는 **관문을 통과한 뒤** 지킬 것.

- **포지션 사이징은 손절가가 아니라 최악 갭 기준으로.** 하방 LULD 홀트 중에는 주문이
  체결되지 않고 재개 시 5~10%+ 갭이 난다. 최대손실 1% 목표면 포지션은 계좌의
  1.25~2% 상한. **≤1/4 Kelly** (풀켈리는 자본이 X% 까지 갈 확률이 X%).
- **주문가에 반올림값을 쓰지 마라.** A4 의 반올림은 표시·분석용이다. 주문가가 필요하면
  응답 원문 문자열을 별도 보존해야 한다.
- **주문량은 실시간 거래량의 1~5% 이하로 제한.** 초저유동성 종목에서 본인 주문이
  가격을 미는 반복 패턴은 시세관여로 재구성될 수 있다.
- **덤프 방어**: 조건주문 `SINGLE`(MARKET)이 stop-market 상당으로 서버측 예치 가능.
  OCO 는 지정가만이라 갭다운 미체결 리스크가 있다.
- **어텐션 피크 = 청산 카운트다운** (Barber 2022). VWAP 상실·First Red Day 는 무조건 청산.
- **집행은 SOR + 지정가만, 시장가 금지** (2026-08-02 사용자 확정).
- **절대 금지**: 자전거래성 매매, 허수 주문, 커뮤니티 선동, 리딩방 지시 동조.
  우리는 공개 신호에 대한 순수 테이커다.
