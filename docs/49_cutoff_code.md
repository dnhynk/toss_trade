### 2-3. `measure/rule_search.build_events` (캔들 **양쪽**)

`docs/47` §5 표 #37 이 남긴 항목은 "pre `<t0` / post `>=t0` **양쪽의 이동 방향**" 이었다.
종료 라벨 규약을 양쪽에 같은 규칙("라벨 `t0` 봉은 `t0` 에 속한다")으로 적용하면
**형태가 대칭이 아니다**:

```diff
-  pre :  ts_ms >= t0-240m AND ts_ms <  t0        post:  ts_ms >= t0 AND ts_ms <= t0+390m
+  pre :  ts_ms >= t0-240m AND ts_ms <= t0        post:  ts_ms >  t0 AND ts_ms <= t0+390m
```

- **pre `<=`**: T0 봉은 t0 에 완결이므로 **관측 가능** → 신호에 속한다 (A2 §1).
- **post `>`**: 라벨 t0 봉의 **내용은 t0 이전**이다. 그대로 두면 ① 그 봉이 pre 와
  **중복**되고, ② 청산 시뮬레이터(`rules.simulate`, `path["ts_ms"] >= entry_ms`)가
  **진입 전에 지나간 1분의 고가·저가로 목표가/손절을 체결**시킨다.
- 진입가 `t0_u`(= T0 봉 종가)는 이제 `pre` 에서 뽑는다.
- `flow` 창은 `(t0, t0+30분]` = **내용 `[t0, t0+30분)`** 이 되어 "T0 이후 유동성" 이라는
  이름과 실제가 일치한다(전에는 `[t0−60초, t0+30분)` 로 진입 전 1분이 섞여 있었다).

경계를 **절대 시각 테스트로 고정**하기 위해 두 질의를 `event_frames(conn, sym, t0)` 로
분리했다 — parquet 픽스처 없이 경계만 검사할 수 있어야 했다. 로직 변경은 없다.

## 4. ★ 확인 관측 (2)-b — `rvol_at_cutoff == rvol_at_t0` **실측**

사전등록 §3 상자가 자기 진술을 **미실측**으로 표시하고 관측 하나를 지정했다:

> 개정 후 이벤트마다 **`rvol_at_cutoff` 와 라벨 `rvol_at_t0` 가 일치하는가.**
> 일치하면 위 동어반복이 확정이고, 불일치하면 위 진술 전부를 재검토해야 한다.
> **실측 소유는 W3.**

`tossmon/analysis/measure/cutoff_tautology.py` 로 쟀다. 라이브 콜 0, DB `mode=ro`,
train 상한(2026-01-01 미만)만 읽고 **홀드아웃 열람 없음**.

**표본**: 백필 DB 실봉, 심볼 7개(DVLT SLNH CYPH BYND INHD ATCH CYCU), **이벤트 60건**.
게이트는 사전등록 §2.1 기본값(`window_min=30, ret_min=0.15, day_ret_min=0.30,
rvol_min=3.0, max_per_day=1`), 피처와 게이트에 **같은 `curve`** 를 넘겼다.

| 관측 | `obs_le` (`<=`) | `strict_lt` (`<`) |
|---|---|---|
| `rvol_at_cutoff == rvol_at_t0` **정확 일치** | **60 / 60 = 1.000** | 0 / 60 = 0.000 |
| `cutoff_lag_min == 0` | 60 / 60 = 1.000 | (구조적으로 ≥ 1) |
| 게이트 `rvol_at_t0 >= 3.0` | 60 / 60 | — |

**판정: §3 의 동어반복 진술은 실측으로 확인됐다.** `<=` 에서 `rvol_at_cutoff` 는
게이트가 검사하는 바로 그 양과 **부동소수점까지 같은 수**다. 기전은 `rvol_series` 가
**인과적 단일 전진 패스**(`running += v`)라는 것 — t0 이후를 잘라내도 t0 에서의 값이
변하지 않는다. 그리고 `strict_lt` 에서 0/60 인 것이 대조군이다: 같아지는 것은 개정의
결과이지 원래부터 같은 두 양이 아니었다.

**캘린더 유보(정직하게).** 이 워크트리에 phase1c 산출물도 저장된 분석 캘린더도 없고
라이브 호출은 금지라, 캘린더를 **일봉 ts(=00:00 ET, `docs/06` §2-2) + 세션 오프셋
(`docs/01` §5)** 에서 역산했다. 실측 적합도: 봉의 **100.0%** 가 재구성된 매매일 안,
**100.0%** 가 세션 안(37,727봉 기준).

여기서 내 계측기가 **한 번 틀렸다가 고쳐졌다.** 처음에 세션 길이를 스펙 유래 합성
픽스처(`market_calendar_us.json`, `source: synthetic`)에서 읽어 `day=470 / after=120`
으로 잡았더니 세션 적합도가 **89.4%** 로 떨어졌다. **라이브 캡처**
(`live_market_calendar_us.json`, `source: live`)는 `day=480 / after=230` 이고,
`docs/01` 도 §5 표에는 스펙값(09:00–16:50)을, 데이마켓 항목에는 실측 **17:00** 을
싣고 있다. 실측값으로 바꾸자 적합도가 **100.0%** 가 됐다. 아래 수치는 전부 실측 캘린더판이다.
(틀린 판에서도 §4 의 60/60 · 0/60 과 §5 의 θ=2·3 = 1.000 은 **동일**했다.
바뀐 것은 §5-1 의 θ=5 한 건뿐이고, 그것은 아래에 적었다.)

두 경로가 **같은 캘린더·같은 곡선**을 쓰므로 캘린더 오차는 양쪽에 똑같이 실려
**일치/불일치 결론에는 상쇄**된다 — 위 사고가 그것을 우연히 실증했다. 다만
**절대 rvol 값과 위 60건이라는 표본은 등록 표본이 아니다** — 이 수를 §4 판정에
인용하면 그 결론은 무효다.

## 5. ★ 확인 관측 (3) — 두 번째 동어반복도 **맞다**

태스크 질문: `rvol_first_cross_{2,3}_lead_min` 의 **검출률이 구조적으로 1.000 이 되는가.**

같은 60건에서:

| θ | 검출률 `obs_le` | 검출률 `strict_lt` | 리드 0 건수(`obs_le`) |
|---|---|---|---|
| **2.0** | **60/60 = 1.000** | 56/60 = 0.933 | 6 |
| **3.0** | **60/60 = 1.000** | 46/60 = 0.767 | 15 |
| 5.0 | 47/60 = 0.783 | 41/60 = 0.683 | 6 |

**판정: W7 의 구조적 예측이 맞다.** θ=2·3 의 검출률은 `obs_le` 에서 **1.000**이고
이것은 데이터가 아니라 정의에서 나온다 — 게이트가 `rvol_at_t0 >= 3.0` 을 보장하고,

### 5-1. 덤으로 나온 것 — **리드 0 병기 장치가 옛 검출률을 정확히 복원하지 못한다**

## 8. 혼자 내린 판단 — 자기 신고

물어보지 않고 내가 정한 것들이다. 되돌릴 근거가 있으면 되돌려야 한다.

1. **`include_t0` 기본값을 `False` → `True` 로 뒤집었다.** A2 §1 이 "기본값은 관측 가능

2. **`cutoff_mode` 라는 새 피처 키를 만들지 않았다.** 기존 `include_t0` 값(1.0/0.0)이
   이미 모드 태그라서, 키를 늘리면 "키 집합은 항상 동일" 계약의 소비자와 저장 스키마를
   건드린다. 표기 규약은 docstring 에 매핑으로 적었다. **다르게 원하면 말해 달라.**
3. **`rule_search` 의 post 를 `>= t0` → `> t0` 로 바꿨다.** A2 문언은 "컷오프" 만

   pre·post 에 **중복**되고 진입 전 1분으로 목표가가 체결된다는 것이다(§2-3).
   **이것이 이번 수정에서 유일하게 성과 수치를 자기불리 방향으로 미는 변경**이다(§6 #11).
4. **`event_frames` 헬퍼를 새로 만들었다.** 절대 시각 테스트를 붙이려면 parquet 픽스처
   없이 경계만 부를 수 있어야 했다. 로직은 옮기기만 했다.
5. **캘린더를 일봉에서 역산했다**(§4 유보). 저장된 캘린더가 이 워크트리에 없고 라이브가
   금지라 다른 길이 없었다. 적합도(100.0% / 100.0%)를 함께 실었고, 결론이 그 오차에
   견고한 이유도 적었다. **등록 표본이 아니라는 점은 §4 에 명시했다.**
   **세션 길이를 합성 픽스처에서 읽어 한 번 틀렸다** — 라이브 캡처로 고쳤고 그 경위와
   틀린 판의 수치 차이를 §4 에 남겼다. 두 픽스처가 다르다는 사실 자체는
   `docs/01` §5 표(스펙)와 데이마켓 항목(실측)의 불일치로도 이미 문서에 있다.
6. **실측 표본을 심볼 7개·이벤트 60건으로 잡았다.** 구조적 동일성 확인에는 충분하다고
   판단했다(1.000 / 0.000 로 갈렸다). 더 큰 표본이 필요하면 인자로 늘릴 수 있다:
   `python -m tossmon.analysis.measure.cutoff_tautology <db> <n_symbols>`.
7. **§5-1 은 아무도 요구하지 않은 관측이다.** 태스크 3번을 재다가 `recovers_strict_detect`
   가 false 로 나와서 가설·반증 절차를 밟아 확인했다. 판정하지 않고 요구로만 넘긴다(§7-1).
