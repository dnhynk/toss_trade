## 라이브 리허설 시 추가 실측 (리스 부여 후에만 실행 — W1 미완 항목)
W1의 실측은 전부 프리마켓 시간대였다. 아래는 미측정이며 설계 검증에 필요하다:
1. `tools/live_probe.py --probe quote_realtime,orderbook_depth,trades` 를
   **정규장(22:30–05:00 KST)과 데이마켓(09:00–17:00 KST)에 각각** 실행.
   특히 **데이마켓의 소형주 `no_print` 비율**이 핵심이다 — A2 의 `first_print` 승격 트리거가
   실제로 동작하는지가 여기에 달렸다.
2. **1분봉 보관 경계 이분탐색**: W1이 1024일 hit / 2048일 miss 까지만 좁혔다.
   `candle_deep` 프로브를 확장해 약 10콜로 경계를 좁혀라. 종목별로 다를 수 있으니
   대형주 1 + 소형주 1로 각각 측정하라. 백필 계획(docs/03 §1-A)의 규모 산정에 직결된다.
3. 결과는 `docs/08_runbook.md` 에 기록하고, `docs/06_live_facts.md` 는 W1 소유이므로
   수정하지 말고 코디네이터에게 보고하라 (코디네이터가 반영한다).

**프로브 소요시간 (W1 인수인계 — 실행 계획에 반영하라)**
- `quote_realtime` 은 기본 6폴링 × 12초 ≈ 60초, `rankings` 는 2타입 × 4폴링 × 20초 ≈ 160초다.
  세션당 수 분이 걸리므로 세션 시간 안에 끝나도록 시작 시각을 잡아라.
- **데이마켓은 세션 초반(09:00~10:00 KST)과 중반을 나눠 두 번 측정하라.**
  유동성이 가장 얇은 구간이 `first_print` 트리거의 **최악 조건**이기 때문이다.
  **성공 기준**: 최악 조건에서도 `first_print`/`staleness` 신호가 의미 있게 동작해야 한다.
  동작하지 않으면 A2 의 Tier1 승격 설계 자체를 재검토해야 하므로 **즉시 escalate** 하라.

**토큰 위생**: 리스를 받으면 `data/token_state.json` 이 새로 생긴다. 리허설 종료 후
파일락이 반납됐는지(`.lock` 파일 부재) 확인하고, 상태파일 처리 지침을 런북에 명문화하라.
파일 삭제는 로컬 사본만 지울 뿐 **서버측 토큰을 무효화하지 않는다** — 런북에 이 사실을 정확히 적어라.

## 불변 규칙 (위반은 반송 사유)
1. **라이브 API 리스**: client당 유효 토큰 1개 — 리스 보유자 1개만 실서버 호출 가능.
   코디네이터가 명시적으로 리스를 부여하기 전까지 너는 mock 전용이다.
   `api_keys` 읽기·토큰 발급·실서버 호출 시도는 즉시 작업 중단 사유.
2. **계약 불변**: 시그니처·규약 변경 금지. 필요하면 `ask`.
3. **파일 소유권**: 소유 경로 밖 파일 생성·수정 금지. 필요 시 `ask`.
   완료 시 `git diff --stat $(git merge-base main HEAD)..HEAD` 로 증명하라.
4. **거래 코드 금지**: 주문/조건주문/계좌변경 코드를 어떤 형태로도 만들지 않는다.
5. **시크릿**: `api_keys` 내용을 출력·로그·커밋·메시지에 절대 포함하지 않는다.
   시크릿 스캔 훅을 만들면서 실제 시크릿을 테스트 픽스처에 넣지 마라 (가짜 패턴을 쓸 것).
6. **브랜치**: 자기 브랜치에만 커밋. `main` 직접 커밋·머지 금지.
7. **하위 분기 금지**.
8. **컨텍스트 위생**: 지정된 문서만 읽는다.
9. **테스트 없는 완료 금지**.
10. **보고 포맷** — `worker_done` 시 (a)~(e). 정확히 1회, ID 포함, 이후 idle.
11. **에스컬레이션**: 설계 전제를 깨는 발견이면 즉시 escalate.
12. **"준비됨/완료" 보고 전에 반드시 `git log`로 커밋을 확인하라.**
