# W4 — 백필 앵커 결함 수정 + 재백필 (밤샘 캠페인 A-1, 사용자 포괄 승인 하)

너는 W4 다. 네 진단이 수리됐다: 창당 단일 끝 앵커 후진 페이징 + merge_spans 광역화가
원인, 창의 88.6%가 요청 구간 25% 미만 수집. **오래된 쪽 데이터는 보관창이 밀며 매일
소멸 중이다 — 속도가 품질 다음으로 중요하다.**

## 1단계 — 수정 (mock 전용)

네 진단 보고서의 수정 계획 그대로:
- **후보일 단위 앵커링** (`before = D+2` 계열) + **무체결 갭 넘김 재앵커링**
  (nextBefore=None 인데 요청 구간이 남았으면 다음 앵커로 재개).
- `merge_spans` 의 광역 병합이 앵커 희석을 일으키지 않도록 재설계(후보일 기준 계획).
- **체크포인트 재구동**: 기존 done/partial 창을 새 계획으로 다시 받게 하되, 이미 받은
  봉은 중복 없이(INSERT OR IGNORE 류) — 기존 1.77M 봉은 자산이다, 버리지 마라.
- **현실 밀도 회귀 테스트**: "한정 깊이 + 무체결 갭에서 nextBefore=None" 을 흉내내는
  네 소유 테스트 더블로 — **W1 의 tools/mock_server.py 는 수정 금지**(소유권).
  AARD 형 시나리오(후보 41일, 중간 활황일 결측)가 수정 후 전부 수집되는지 단언.
- 전체 pytest green. 커밋은 `w4-collector` 에만.

## 2단계 — 정지선

수정 완료 시 `status` 로 보고(변경 요약 + 테스트 수 + 재백필 예상 호출·시간).
**내 게이트·머지 GO 를 받은 뒤에만** 3단계로.

## 3단계 — 재백필 (라이브, GO 후)

- 슈퍼바이저 하 기동(검증된 nohup 방식), `--from 2025-09-01`,
  `--deadline "2026-08-03 09:00"` (안전 상한 — 추정 6~9h 대비 충분).
- 현재 IP `122.40.242.91` 등록 확인됨. env 에 TOSS_LIVE=1·TOSS_BASE_URL 명시(전례 사고).
- 기동 확인(새 봉 유입) 후 침묵 모드 — 슈퍼바이저 STATUS 가 30분마다 로그에 남는다.
  완료(DONE) 또는 ESCALATION 시에만 보고. 나도 supervisor.log 감시를 재무장한다.
