## 1. M-2 — `iso_to_ms` 가 반올림 대신 절삭한다 [유일한 미해결 확정 항목]

`tossmon/api/models.py:62`: `return int(dt.timestamp() * 1000)`

`datetime.timestamp()` 가 float 이라 `...357.9998` 이 나오고 `int()` 가 357 로 깎는다.
감사 실측: 200만 개 무작위 ms 중 6건 불일치. **분 정렬(봉)·초 정렬은 0/50만** 이므로
캔들과 `nextBefore` 는 영향 없고, 영향받는 것은 **`/trades`·`/prices` 의 실제 ms 타임스탬프**다.

왜 고치는가: `trades_snap` 의 PK 가 `(symbol, ts_ms, price_u, qty_u)` 라
**1ms 어긋나면 같은 체결이 다른 행으로 들어간다.** 테이프 표본 통계가 조용히 부풀 수 있고,
`last_trade_ms` 비교로 테이프 누락을 판정하는 로직도 1ms 오차에 걸린다.

수정: `round(dt.timestamp()*1000)` 또는 정수 연산. 회귀 테스트로 고정하라
(감사가 쓴 200만 건 무작위 대조를 축소판으로 옮기면 된다).

## 2. 소유 경로 잔여 항목 전수 점검 [이게 본체다]

두 감사 문서(`docs/10_audit.md`, `docs/10_audit_b.md`)에는 **M급·L급 항목이 다수** 남아 있다.
그런데 **네가 이미 감사수정 태스크에서 고친 것도 섞여 있다** — 내가 확인한 것만도
M-1(`error_description` 로그 유출)과 M-11(dot segment)은 이미 해소돼 있었다.

그래서 네 일은 "목록대로 고치기"가 아니라 **현재 코드 기준으로 상태를 확정하는 것**이다:

1. 두 감사 문서에서 **네 소유 경로(`tossmon/api/**`, `tools/live_probe.py`,
   `tools/mock_server.py`)에 해당하는 모든 항목**을 뽑아라 (F/H/M/L 등급 전부, 미확인 절 포함).
2. 각 항목을 **현재 main 코드에서 재현 시도**하고 셋 중 하나로 분류하라:
   - **이미 해소** — 어느 커밋에서 어떻게 해소됐는지, 재현이 실패함을 보여라
   - **미해결** — 재현 결과를 인용하고 **고쳐라**
   - **수정 안 함** — 왜 고치지 않는 것이 옳은지 근거를 적어라
     (예: 네가 M-7 을 `LIVE_HOST_MARKER` 가드로 의도적으로 남긴 것처럼)
3. 결과를 **표로** (a)~(e) 보고에 실어라. 이 표가 "감사 대응 완료" 판정의 근거가 된다.

**추측으로 "이미 고쳐졌을 것"이라고 넘기지 마라.** M-1·M-11 처럼 실제로 고쳐진 것과
M-2 처럼 남아 있는 것이 섞여 있다. 재현이 판정 기준이다.

## 3. 미확인 항목 중 네가 답할 수 있는 것

감사 "미확인" 절에 네 영역 항목이 있으면 **mock 으로 해소 가능한지** 판단하라.
라이브가 필요한 것(예: `X-RateLimit-Limit` 실제 단위)은 **손대지 말고 목록만 남겨라** —
W5 가 리스를 갖고 있으니 내가 그쪽에 넘긴다.

## 불변 규칙
1. 라이브 호출 금지, `api_keys` 읽기 금지, W5 DB 접근 금지.
2. 소유 경로 밖 수정 금지. 완료 시 `git diff --name-only $(git merge-base main HEAD)..HEAD` 로 증명.
3. `git rebase main` 먼저 (main 은 감사수정·유니버스 필터 전부 머지됨, 710 tests green).
4. `main` 직접 커밋 금지. 보고 전 `git log` 확인.
5. 계약 문구와 코드가 어긋나면 코드를 맞추지 말고 **(c)에 갱신 요청**을 적어라
   (`docs/04_contracts.md` 는 코디네이터 소유다).
6. `worker_done` 정확히 1회, 보고 (a)~(e).
