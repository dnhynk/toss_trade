## 2. 고칠 것 넷

### 2-1. 공백 판정을 §6-2 로 대체

```
창 [lo, hi] = 13:30~20:00 UTC,  window_s = 23400.0
S = 그 창 안 rankings_snap 의 정렬된 distinct snap_ms (전 ranking_type 합산 — 기존 그대로)

head_s     = (S[0]  - lo) / 1000
tail_s     = (hi - S[-1]) / 1000
interior_s = sum over consecutive pairs of  max(0, (S[i+1]-S[i])/1000 - 60)

unobserved_s    = head_s + tail_s + interior_s
unobserved_frac = unobserved_s / 23400

무효  <=>  unobserved_frac > 0.005        (0.5% = 117.0 초)
```

- **`GAP_LIMIT_S = 60` 은 남는다.** 이제 *"무효 문턱"* 이 아니라 *"정상 간격의 상한"* 이다.
  주석으로 그 역할 변경을 적어라
- **앞머리·꼬리는 전액 센다.** 60 초 면제를 거기 주지 마라 — §6-2 설계 근거 3 이
  그 이유를 적었다(사용자가 문턱을 고를 때 본 숫자가 전액 기준이었다)
- 기존 `find_gaps` 는 **진단 출력에 그대로 남겨라.** 공백 목록은 여전히 쓸모 있다.
  다만 **판정하는 것은 총량**이다
- 출력에 `head_s / tail_s / interior_s / unobserved_s / unobserved_frac` 을 **전부** 찍어라.
  읽는 사람이 손으로 검산할 수 있어야 한다
- §3-4.4 `PARTIAL` 가장자리 규칙: 이제 **head/tail 이 총량에 직접 들어가므로** 별도
  `PARTIAL` 판정과 겹친다. **네가 정하고 근거를 적어라** — 둘 다 두든 하나로 합치든,
  *"왜 그렇게 했는지"* 를 출력과 PR 본문에 남기면 된다. 새 숫자는 지어내지 마라

### 2-2. 밴드 경계 (§6-6a)

| | 늘었다 | 판정 보류 | 안 늘었다 |
|---|---|---|---|
| 옛 (n=10) | > 25.9% | 17.1 ~ 25.9% | < 17.1% |
| **새 (n=6)** | **> 25.9%** | **19.0 ~ 25.9%** | **< 19.0%** |

**통과선 25.9% 는 안 바뀐다. 아래 경계만 17.1 → 19.0.**
`BOUNDARY` 처리(얼린 상수 vs 정확값)는 네가 만든 그 구조를 유지해라.

### 2-3. 기준선 상수 (§6-6)

**10 행 자가검사 표는 그대로 둔다** — 그건 *"DB 가 안 변했는가"* 를 보는 데이터 무결성
검사이고 유효/무효와 무관하다. **바뀌는 것은 요약(밴드를 뽑는 집합)이다.**

```

무효 4 세션: 2026-07-31(2.262%), 2026-08-04(0.637%), 2026-08-05(16.903%), 2026-08-07(0.876%)

새 요약  top-10 : n=6  min 8.6%   중앙 19.0%  max 25.9%
        top-100: n=6  min 4.5%   중앙  6.0%  max  8.0%
```

- 10 행 표에 **세션별 `unobserved%` 와 `VALID/INVALID` 열을 추가**해라. 왜 6 개만 요약에
  들어가는지가 표 안에서 보여야 한다

- 자가검사가 어긋나면 여전히 **판정 거부 + 0 아닌 종료**
