## 2. 무엇을 만드나

`ops/watchdog.ps1` 이 수집기를 죽이기 **직전에** 표본을 파일로 남긴다.

### 2-1. ★ 삽입점 — 실측으로 박아 둔다

`ops/watchdog.ps1` **867~872 행**. 아래 `taskkill` 루프 **바로 앞**이다:

```powershell
    # kill remnants first so a half-dead tree cannot double-run against the API lease
    $rem = @(Get-TossProcs $SupervisorPattern) + @(Get-TossProcs $CollectorPattern)
    foreach ($p in $rem) {
        try { & taskkill /PID $p.ProcessId /T /F 2>&1 | Out-Null } catch { }
    }
```

**`$DryRunRestart` 분기(860~865)보다 뒤, `taskkill` 보다 앞.** 그 사이에서만 살아 있는
프로세스를 관측할 수 있다.

### 2-2. 무엇을 뜨나 — **최소한 이 넷**

| # | 무엇 | 왜 |
|---|---|---|
| 1 | **스택** — 살아 있는 파이썬 프로세스 전부 | *"살아 있는데 일을 안 한다"* 의 유일한 직접 증거 |
| 2 | **IO 카운터 · 핸들 수 · 스레드 수** | 08-21 에 재기동이 2.7 GB 를 되돌렸다 — 무언가를 붙들고 있었다 |
| 3 | **프로세스 트리** (PID·부모·우선순위·CPU·working set) | 사슬 넷 중 어느 것이 멎었는지 |
| 4 | **직전 워치독 판단값** (`col_up`·`t2book`·`rank_age`·`age_min`) | 이미 계산돼 있다. 표본과 같은 파일에 묶어라 |

**선행 조건 — `py-spy` 가 없다.** 새 기계에서도 확인했다 (PATH · `w5-ops` venv 둘 다,
`ModuleNotFoundError: No module named 'py_spy'`). **그것부터 설치해라**:
`.venv/Scripts/pip install py-spy`. 설치 자체를 §7 에 보고해라 (버전 포함).

### 2-3. ★★ 깨뜨리면 안 되는 것 — **자가 복구는 어떤 경우에도 진행돼야 한다**

**이것이 이 작업의 제일 큰 위험이다.** 08-21 저녁에 워치독의 자가 복구가 처음으로
제 몫을 했다(13 초 만에 되살렸다). **표본을 뜨려다 그 안전망을 깨면 순손실이다.**

지켜야 할 것 셋:

1. **증거 수집 전체를 `try/catch` 로 감싸고, 실패해도 `RESTART` 는 그대로 진행한다.**
   `py-spy` 가 없든, 권한이 없든, 예외가 나든 **재기동을 막으면 안 된다**
2. **시간 예산을 박아라.** 증거 수집이 오래 걸리면 그만큼 수집 공백이 길어진다.
   **상한을 명시하고 넘으면 포기하고 죽여라.** 상한값과 그 근거를 §7 에 적어라
3. **`$DryRunRestart` 경로에서는 죽이지 않으므로**, 그 분기에서도 표본이 떠지는지
   따로 판단해서 결정하고 **그 결정의 근거를 적어라**

> `restart_budget_exhausted`(851~858) 로 재기동을 **포기하는** 경로에서도 표본을 뜰지
> 결정해라. 그때야말로 사람이 볼 증거가 필요하다 — 다만 판단은 네가 하고 근거를 적어라.
