= W3 — Q1 판정 방식을 고쳐라: **"선행 셀이 있나"가 아니라 "선행이 후행보다 센가"**

훌륭했다. 홀드아웃 누출을 스스로 잡아 **코드로 막은 것**(`session.drop_holdout`, 버린 수
297,506 / 남긴 수 582,293 을 산출물에 실은 것)이 이번 작업의 최대 성과다.
캔들이 백필이라 봉인 구간을 품고 있다는 걸 아무도 짚지 않았다. 사전등록이 실제로 지켜졌다.
Q0 도 좋다 — 함축 윈도우 **15분**(비율 0.999)으로, 랭킹 점유율이 1분 미만 움직임을
선행할 수 없다는 판단이 실측으로 뒷받침됐다.

## 그런데 판정 규칙에 문제가 있다

내가 라이브 DB(오늘 밤 정규장 추가분 포함)로 재실행했더니 **게이트가 뒤집혔다**:

```
regular   PROCEED   argmax lag -4, leading cells above zero: 1
```

네 스냅샷에서는 `regular lag +1` 이 0 을 교차했는데(+0.0119 [-0.0022,+0.0244]),
데이터가 늘자 **0 초과**가 됐다(+0.0194 [+0.0022,+0.0344]).

**즉 지금 규칙은 실행 시점에 따라 답이 바뀐다.** 사전등록 규칙이 그러면 안 된다.

## 진짜 그림은 대칭이다

정규장 lag −1 / 0 / +1 을 나란히 놓으면:

| lag | n | 차이 | 95% CI | 판정 |
|---:|---:|---:|---|---|
| −1 | 99,430 | **+0.0192** | [+0.0061, +0.0344] | 0 초과 |
| 0 | 114,966 | **+0.0204** | [+0.0035, +0.0383] | 0 초과 |
| +1 | 99,781 | **+0.0194** | [+0.0022, +0.0344] | 0 초과 |
| +2 | 89,985 | +0.0005 | [−0.0158, +0.0110] | 0 교차 |

**−1·0·+1 이 거의 같은 크기고 ±2 에서 0 으로 꺼진다.**
이건 **선행이 아니라 동시 관계**다. 그리고 사용자 실전 감각과 일치한다 —
사용자는 **"거의 동시였던 것 같아"** 라고 했다.

## 두 가지를 고쳐라

### 1. **비대칭 검정**으로 바꿔라 (주 판정)
"선행 셀이 하나라도 0 을 넘나"는 셀이 55개(세션 5 × lag 11)라 **다중검정에 무방비**다.
올바른 질문은:

> **선행 쪽이 후행 쪽보다 유의하게 센가?**

- 지표: `corr(+k) − corr(−k)` 를 k=1..5 에서. **쌍체 부트스트랩 CI.**
- 대칭이면 이 값이 0 이고 → **선행 없음 → 거래 불가**. 지금 데이터가 그렇게 보인다.
- 이 지표는 **동시 관계라는 공통 성분이 상쇄**되므로 위 아티팩트에 면역이다.
- 다중검정 보정(본페로니 등)을 명시하라.

### 2. **경제적 유의성을 함께 내라** (통계적 유의성만으로는 무의미)
n ≈ 100,000 이면 **상관 0.02 도 유의해진다.** 그러나 0.02 는 분산의 0.04% 다.
- 신호를 실제 매매 규칙으로 바꿨을 때 **분당 몇 bp** 인지 환산하라.
- 그 값을 **정규장 실측 비용(유효 스프레드 0.46% + 수수료 0.2%)** 과 비교하라.
- **"유의하지만 먹을 게 없다"가 결론이면 그렇게 써라.** 그게 가장 정직한 형태다.
