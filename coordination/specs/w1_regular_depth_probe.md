= W1 — **정규장에 호가 다단계가 없다.** API 로 받을 수 있는지 지금 확인하라 (시간 민감)

**정규장이 지금 열려 있다(KST 22:30~05:00). 이 창이 닫히기 전에 확인해야 한다.**

## 문제 (코디네이터 실측)

`orderbook_snap.depth_json` 은 전 세션 100% 저장돼 있지만 **내용이 세션마다 다르다**:

| 세션 | n | 레벨 중앙값 | 2레벨 이상 비율 |
|---|---:|---:|---:|
| **day(주간거래)** | 3,258 | **10** | **0.999** |
| **REGULAR(정규장)** | 7,595 | **1** | **0.000** |
| pre(프리마켓) | 14,875 | 1 | 0.000 |
| after(애프터) | 504 | 1 | 0.000 |

실제 저장 내용:
```
[day]     {"asks":[{...},{...},{...} ... 10개], "bids":[... 10개]}
[REGULAR] {"asks":[{"price_u":262900,"qty_u":1000000}], "bids":[{"price_u":235500,...}]}
```

**즉 정규장에는 L1 밖에 없다.**

## 왜 치명적인가

- **$100 초과 클립의 비용을 정규장에서 계산할 수 없다.** W3 의 세션별 비용표가
  정규장 $500/$1000/$2000 칸을 전부 `n/a` 로 낸다.
- 전략 생사가 **클립별 비용**에 걸려 있다. 사용자 직감은 **$2,000 도 문제없었다**인데
  **거래할 세션에서 그걸 측정할 방법이 지금 없다.**
- 즉 이건 지금 우리가 할 수 있는 **가장 값어치 있는 수집 개선**이다.

## 작업 — 지금 정규장 중에 하라

1. **라이브 프로브**: 정규장 중 실제 종목 몇 개(우리 $2~5 대역 포함)에 대해
   호가 엔드포인트를 호출해 **응답에 몇 레벨이 오는지** 직접 확인하라.
   - 주간거래 때 10레벨을 주던 **그 엔드포인트/파라미터 그대로** 호출했을 때 어떻게 되는지
   - 파라미터(레벨 수 요청, 시장 구분 등)를 바꾸면 달라지는지
   - **다른 엔드포인트**로 다단계가 오는지
2. **판정 세 갈래로 명확히**:
   - (A) API 가 정규장에 다단계를 **주는데 우리가 안 받고 있다** -> 수집기 수정(W4 인계)
   - (B) API 가 정규장에 **L1 만 준다** -> 근본 제약. 그러면 **대안**을 제시하라
     (체결 테이프로 깊이 추정, 호가 잔량 시계열로 소진 추정 등)
   - (C) 조건부(종목·승격 상태에 따라 다름) -> 조건을 특정하라
3. `docs/06_live_facts.md` 에 **세션별 호가 깊이**를 사실로 기록하라.
   이건 우리가 몰랐던 API 성질이고, 앞으로 누구도 다시 헛짚으면 안 된다.

## 규율

- **읽기 전용 호출만.** 주문·조건주문·계좌 계열 **금지**(계약 §406).
- 가동 중 수집기를 건드리지 마라. 프로브는 **별도 세션/키**로, 호출 수는 **최소**로.
  (수집기가 같은 레이트리밋을 쓰고 있다 — 수집을 방해하면 안 된다.)
- 응답 원문을 `docs/06` 에 붙일 때 **계정 식별자·토큰 제거**.
