# W4 — 백필 세션 내 공백 진단 (분석이 §1.7 감사로 정지 — 원인 판별 긴급)

너는 W4 다. Phase 1-C 분석이 사전등록 §1.7 기저율 감사에 걸려 정지했다. 실측:
**이벤트일 정규장 봉 충전율 중앙값 10% (390분 중 40봉)** — 급등일인데 90%가 비어 있다.
지금 필요한 것은 "소형주 원래 희소" 대 "백필이 덜 받아옴"의 **판별**이다.

**라이브 호출 금지** (진단은 전부 오프라인 — 로컬 DB·코드·매니페스트만).
W5 수집 DB 는 읽기 전용.

## 진단 항목 (전부 오프라인, 우선순위순)

1. **접지 대조 (결정적)**: 07-30~07-31 라이브 수집 DB
   (`w5-ops/data/tossmon.db`, 읽기 전용)에는 감시 종목의 1분봉이 실시간 수집돼 있다.
   라이브에서 이벤트가 확정된 (심볼, 매매일) 5~10개(CIGL·PLYX·SNTI·BTAI·AFRIW·STAK 등)에
   대해 **같은 (심볼,일)의 봉 수를 backfill.db 와 대조**하라. 수집 DB 가 훨씬 많으면
   백필 미달 확정, 비슷하면 시장 현실.
   주의: 두 DB 의 세션 경계·심볼 표기·ts 단위를 맞춰 비교하라.
2. **페이지 상한 검사**: `tools/backfill.py` 의 창당/일당/호출당 페이지네이션 로직을
   정독하라 — per-window 호출 상한, `before` 페이징 종료 조건, 페이지 크기 가정(200봉?),
   밀집일에서 조기 종료할 수 있는 모든 경로. 특히 "예상 콜 수" 계산이 실행 경로에
   상한으로 새어 들어갔는지. mock E2E 는 밀도가 낮아 이걸 못 잡았을 것이다.
3. **매니페스트 역추적**: partial/done 창 몇 개를 골라 창별 기록(요청 구간·수집 구간·
   호출 수)과 DB 실봉수를 대조 — 창이 "완결" 표시인데 세션 중간이 비는 패턴이 있는가.
4. **API 특성 가설도 배제**: docs/06 의 before-inclusive·페이지 크기 실측과 대조해
   페이징 산술 자체의 off-by-one/조기종료 가능성 점검.

## 보고

- `worker_done` 1회(ASCII), 핵심 = **판정: 미달인가 현실인가**, 미달이면 **정확한 결함
  위치 + 영향 범위(몇 창이 얼마나 비었나) + 수정·재백필 계획**(체크포인트가 done 으로
  기록한 창을 다시 받게 하는 방법 포함 — 재실행 시간 추정과 함께).
- 수정은 이 태스크에서 하지 마라 — 진단·계획까지. (수정+재백필은 별도 승인.)
- 소유 경로 밖 수정 금지. 라이브 0콜.
