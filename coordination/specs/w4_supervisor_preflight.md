# W4 — 슈퍼바이저 디스크 preflight (백로그 소진, 소규모)

너는 W4 다. 네가 직접 백로그로 남긴 항목이다: 백필 중 디스크가 가득 차
`OSError: [Errno 28]` 로 체크포인트 저장이 실패했고, 슈퍼바이저는 이를 **일반 크래시로
분류해 3연속 재시도 후 포기**했다. 원인이 코드가 아니라 디스크였는데 로그만 봐서는
알 수 없었다(코디네이터가 수동 진단·정리 후에야 복구).

**라이브 호출 금지** (mock 전용). 가동 중 수집기·DB 접근 금지.

## 작업 (`tools/backfill_supervisor.py` + 테스트)

1. **기동 전 preflight**: 여유 공간이 임계 미만이면 러너를 띄우지 말고 명확히 보고
   (`ESCALATION:` 라인 + 사유 = 디스크). 임계값은 네 판단(예상 산출 크기 기반).
2. **크래시 분류에 디스크 추가**: 러너 로그/종료 코드에서 `Errno 28` 계열을 식별하면
   **재시도 스트라이크를 소모하지 말고** `DISK-FULL` 로 즉시 에스컬레이션.
   무의미한 재시도 3회로 스트라이크를 태우는 현 동작을 고친다.
3. **주기 점검**: STATUS 라인에 여유 공간을 포함(이미 있으면 임계 근접 시 경고 승격).
4. 회귀 테스트: preflight 차단, Errno 28 즉시 에스컬레이션(스트라이크 미소모),
   여유 회복 후 정상 기동. stash 로 수정 전 실패 증명.

## 참고

W5 의 수집기 워치독(`ops/watchdog.ps1`)에는 이미 디스크 감시가 있다 — **중복 구현 말고**
슈퍼바이저(백필용) 쪽만 고쳐라. 두 층의 역할이 다르다.
