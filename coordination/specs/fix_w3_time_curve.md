## 왜 지금인가 — 감사의 분류를 코디네이터가 상향한다

적대적 감사(`docs/10_audit.md`)는 M-3·M-4 를 "Phase 2 중 정리해도 좋은 것"으로 분류했다.
**그 분류는 사전등록(`docs/12_preregistration.md`)이 나오기 전 기준이다.**

사전등록은 분석을 **과거 백필 데이터**로 하도록 규정한다
(train ~2025-12-31 / val 2026-01-01~04-30 / holdout 2026-05-01~07-29).
그 구간에는 **겨울(EST)과 반일장이 대량으로 포함**된다. 즉 두 결함은
"2026-11-01 부터 발현"이 아니라 **지금 당장 계획된 분석을 오염시킨다.**

→ **Phase 1-C 분석 착수 전 해소 대상으로 격상한다.**

## M-3 — 겨울(EST)에 UTC 날짜 기준 매매일이 갈라진다

`labeling.py:11-13`, `features.py:95` 의 "토스 4세션은 UTC 00:00~22:00 이므로 UTC 날짜 = 매매일"
주석은 **서머타임에만 참**이다. EST 에서는 애프터장이 UTC 자정을 넘는다:
```
EDT 여름: UTC 2026-07-15 00:00 .. 23:49   same-UTC-date = True
EST 겨울: UTC 2026-01-15 01:00 .. 01-16 00:49   same-UTC-date = False
→ 하나의 매매일이 둘로 쪼개진다
```
가장 심각한 곳은 **`features.py:476-502` `_history_features`** 다 —
**캘린더를 줘도 항상 UTC 날짜를 쓴다.** 결과:
```
하나의 매매일(2026-01-15 EST)인데
  hist_days_available = 2.0        (정답 1.0)
  prior_event_count_20d = 2.0      (한 번의 급등이 두 번으로 계산됨)
```
겨울 내내 `hist_days_available` 가 부풀고 **former-runner 프록시가 이중 계산**된다.
former runner 는 우리 유니버스 선정의 핵심 축이므로(docs/02 §2.4) 그대로 두면
**과거 러너 이력이 조작된 채로 분석에 들어간다.**

수정: `_history_features` 에 캘린더/매매일 span 을 넘겨 `UsMarketDay` 기준으로 묶어라.
폴백 경로(캘린더 없음)도 겨울을 인지하게 하거나, **최소한 캘린더 없이 호출되면
경고를 내고 그 사실이 결과에 표시되게** 하라 — 조용히 틀리는 것이 최악이다.

## M-4 — 반일장(조기폐장)이 분-of-session 곡선을 오염시킨다

`baselines.py:201-211` 은 `(session, minute_offset)` 로 색인한다. 서머타임 전환에는 안전하지만
**세션 길이 차이에는 무방비**다. 실측:
```
반일장(13:00 ET 조기폐장, 210분)이 곡선에 섞이면
  curve[('regular', 209)] = 2080000000   (정상 100000000 — 20배 오염)
  정상일 minute 209 의 rvol_bar = 0.0481  (정답 1.0)
반일장 당일을 정상일 곡선으로 보면
  반일장 종가의 rvol_bar = 100.0
```
**RVOL 은 이 전략의 1차 스크린**이다(docs/02 §4.1). 20~100배 왜곡은 이벤트 검출을 통째로 뒤집는다.
미국 반일장은 추수감사절 다음날·크리스마스 이브·독립기념일 전날 등 **매년 여러 번** 있고,
백필 구간에 반드시 포함된다.

수정 방향(네 판단):
- 세션 길이를 곡선 색인에 반영(예: 정상일/반일장 분리, 또는 세션 진행률 기반 색인)
- 반일장을 곡선 산출에서 제외하되 **제외 사실과 건수를 드러내라**
- 반일장 당일의 RVOL 을 어떻게 처리할지도 정하라(제외 / 별도 곡선 / 진행률 매핑)
어느 쪽이든 **`docs/07_analysis_spec.md` 에 정의식과 경계조건을 적어라.**
