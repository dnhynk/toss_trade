### 8-1. ★ 내가 틀린 것 둘

**(가) 공백과 밀림을 한 칸 어긋나게 짝지었다.** 내 명세 §1-1 은 `+37s` 밀림을 **72.1 초**

마감을 가로지른 것은 **바로 뒤의 51.9 초짜리**다.

**(나) `auth_refresh` 를 잘못 읽었다.** 명세 §2 에 *"`auth_refresh` 가 창 전체 0 →
토큰 POST 자체가 없었다"* 고 썼는데 **성립하지 않는다.** 그 카운터는 **401 을 받았을
때만** 오르고 **성공한 재발급은 어떤 카운터도 안 올린다.**
**결론(토큰 락 사망)은 살아남지만 근거가 바뀐다** — 살아남은 근거는

(`_issue()` 가 예외를 내면 `async with` 가 풀려 `_alock` 이 놓이고, 재시도는 락 **밖**에서 돈다).

**(다) "두 현상인가" 라는 내 질문 자체가 틀린 전제였다.** 밀림은 기전이 아니라 **산수**다 —
텔레메트리는 *"직전 줄 + 300 초"* 에 찍으므로 **밀림 = (정지 끝 − 마감)** 이고,
정지가 마감 대비 어디 떨어지는지는 우연이라 **기댓값이 정지 길이의 절반**이 된다.

표본 밖 08-14 까지 **오차 0.5 초 안**으로 재현했다. 작은 공백들이 안 민 것은 성질이

> **셋 다 내가 어제 "새 단서" 라고 적은 것들이다.** 산수를 기전으로 읽었고,
> 카운터 의미를 확인 안 하고 추론했다. **워커가 명세를 의심한 것이 옳았다.**

## 9-2. ★ 내가 틀린 것 둘 — 규칙으로 박는다

1. **계획 표식을 세웠으면 복구 실패 시에도 반드시 걷어라.**
   `PLANNED` 는 수집 부재 경보를 `PLANNED_` 로 바꿔 **워치독의 재기동 판단을 끈다.**
   나는 정지에는 성공하고 기동에 실패했는데 표식을 그대로 뒀다. 그 결과
   *"수집기가 죽었는데 아무도 안 살리는"* 17 분을 내가 만들었다.
   → **표식은 기동 성공을 확인한 뒤에 걷는 것이 아니라, 정지 절차를 떠날 때 걷는다.**
2. **에이전트가 거는 예약작업은 반드시 `S4U`.**
   `Interactive` 는 내 대화형 세션 안에서 돌아 **콘솔 이벤트를 같이 맞는다**
   (`Result=3221225786 = STATUS_CONTROL_C_EXIT`). `collector-oneshot` 이 08-04 부터
   같은 코드를 달고 있던 것이 같은 자리다. **다만 S4U 등록에는 관리자가 필요하다** —
   즉 **에이전트는 새 무인 작업을 혼자 못 만든다.** 이 사실 자체를 기록해 둔다.

## 9-3. ★ 진짜 원인은 갈렸다 — **수집기 코드가 아니라 기동 경로다**

같은 워크트리·config·venv 로:

| 경로 | 결과 |
|---|---|
| `python -m tossmon.collector` (직접) | **18 초 만에 정상** — `resumed` -> `collector start` -> `session closed->pre` -> 텔레메트리 -> 테이프 폴 |
| `launch_collector.cmd` -> `ops.supervisor` -> 수집기 | **프로세스 생존 + stdout 0 + DB 0.** 21:28 · 22:08 **두 번 재현** |

**유력 가설**: 자식 stdout/stderr 파이프가 안 빠져 자식이 write 에서 블록된다.
`collector.stdout.log` 가 **204 MB** 이고 `detector.py:787` `RuntimeWarning` 이 초당
여러 줄 쏟아진다(앞단 실행에서 눈으로 확인). Windows 파이프 버퍼는 약 64 KB.
**확정 아니다** — W5 명세 `specs/w5_supervisor_pipe.md` 에 *"반증할 관측을 먼저 진술하라"* 로 넘겼다.

## 9-4. 자가 복구 3 층이 왜 통째로 막혔나

| 층 | 왜 안 됐나 |
|---|---|
| supervisor | 자식이 먹통이라 살아 있어도 수집 0 |
| 워치독 | `RESTART` 가 동기로 막혀 **10 분 뒤 강제 종료**(`ExecutionTimeLimit=PT10M`), `MultipleInstances=IgnoreNew` 라 그동안 트리거 전부 무시 |
| 센티널 | 워치독 하트비트만 보므로 *"fresh"* 라고 보고 — **수집 여부를 안 본다** |

**세 층이 전부 "프로세스가 있다" 를 성공으로 읽는다.** 오늘 그 셋이 동시에 속았다.
