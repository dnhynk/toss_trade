## 1. 사고 — 조용한 워치독 정지

### 1-1. 원인 사슬 (재현 완료)

```
1. 디스크 0 GB
2. Save-State 의 WriteAllText 가 BOM 3 바이트만 쓰고 실패
     -> watchdog_state.json = EF BB BF
3. Get-Content -Raw 가 BOM-only 파일에 아무것도 안 내놓는다
4. ConvertFrom-Json 이 그것을 받고 예외 없이 아무것도 안 낸다   <- 227행 try/catch 무력
5. Load-State 가 $null 반환
6. Set-Prop $null -> "null 배열에 인덱스 불가" (244행)
7. $ErrorActionPreference='Stop' -> 종료성 -> 로그 없이 exit 1
```

**4~6 단계를 실제 파일로 그대로 재현했다.**

### 1-2. 왜 아무도 못 잡았나

**하트비트는 죽기 전에 써진다.** 워치독은 매 사이클 `watchdog_heartbeat.txt` 를 쓰고
그 뒤에 죽었다. 센티넬은 *"하트비트 신선 → OK"* 만 보므로 **16:02:54 에도 정상이라고
보고했다.** 감시의 감시가 같은 신호를 봤다.

마지막 워치독 로그는 **15:40:53**, 복구는 **16:35:53**.

### 1-3. 조치

3 바이트 파일을 백업하고 제거했다. `Test-Path` 가 거짓이 되어 `Load-State` 가 정상
경로(`New-Object PSObject`)를 타고, 상태 파일이 7,093 바이트로 재생성됐다.
**잃은 것은 스트라이크 카운터와 경보 중복제거 상태뿐이고 한 사이클이면 다시 쌓인다.**

복구 확인: `2026-08-28 16:35:53 [watchdog] sup=1 col=1 ... col_up=84297s free_gb=24.55
fetch_pct=100 auth_fail=0`. **`col_up=84297s`(23.4 h) 이므로 수집기는 재기동된 적 없다.**

### 1-4. 아직 안 고친 결함 둘

| | 무엇 | 상태 |
|---|---|---|
| **A** | `Load-State` 의 `try/catch` 는 **파싱 예외만** 막고 **빈 반환은 못 막는다.** 디스크가 또 차면 똑같이 재발한다 | **미수정** — 라이브 코드라 배포 창 필요 |
| **B** | 센티넬이 **하트비트 신선도**만 본다. 하트비트는 죽기 전에 써지므로 이 침묵을 원리상 못 잡는다 | **미수정** |

A 의 형태:
```powershell
try { $s = Get-Content $StateFile -Raw | ConvertFrom-Json
      if ($null -ne $s) { return $s } } catch { }
```

### 1-5. 코디네이터 오독 — `procs=0`

수동으로 워치독을 돌렸더니 `procs=0 process_dead` 가 나와 *"다음 사이클이 멀쩡한
수집기를 재기동한다"* 고 판단했다. **틀렸다.**

양성 대조: 같은 질의로 `node.exe` 의 `ExecutablePath` 는 읽히는데 **`python.exe` 넷은
`ExecutablePath` 와 `CommandLine` 이 전부 빈 값**이다. 수집기는 예약 작업의 **S4U 세션**
에서 떴으므로 내 세션에서는 못 읽고 워치독 자기 세션에서는 읽힌다.
**`procs=0` 은 내 실행의 산물이다.** 16:35:53 정규 사이클이 `sup=1 col=1` 로 확인했다.
