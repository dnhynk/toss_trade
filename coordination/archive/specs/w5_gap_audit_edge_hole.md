= W5 — 아침 리포트가 **한 시간짜리 구멍을 3.4분이라고 보고했다**

오늘(08-05) 기계가 **08:01:46 ~ 09:01 KST, 약 60분** 잠들어 수집이 통째로 멈췄다.
`daily_health_20260805.txt` 는 그 창을 포함하는데도 이렇게 적었다:

```
window (KST): 2026-08-04 09:00 ~ 2026-08-05 08:50
rankings_snap rows : 1435198
  poll timestamps  : 14310  max_gap=3.4min  median_gap=0.5s
```

**`max_gap=3.4min`.** 코디네이터가 DB 로 직접 확인한 사실:

```
창 안 마지막 랭킹 폴 : 08-05 08:01:46
창 끝              : 08-05 08:50:00
=> 창 끝에 붙은 구멍 48.2분  <- 리포트에 안 나온다
```

## 왜 안 보이는가

결손 계산이 **연속한 두 폴 사이의 간격**만 본다. 그래서 구멍이 창 **가장자리**에 있으면
비교할 다음 폴이 창 밖이라 간격이 만들어지지 않는다. 창 **앞쪽** 구멍도 같은 이유로 안 보인다.

즉 **수집이 창 끝에서 죽으면 리포트는 "이상 없음"이라고 말한다.**
이건 이 프로젝트가 다섯 번째로 만나는 **"성공을 반환하는 조용한 실패"** 다
(룩어헤드 테스트가 죽은 설계만 지킴 / 분석 함수가 테스트에서만 호출됨 / 가드가 허용목록만
검사함 / pandas 중복 인덱스 브로드캐스트, 그리고 이번).

**그리고 이 리포트는 매일 아침 자동화 코디네이터가 가장 먼저 읽는 문서다.**
여기가 거짓말하면 그날의 판단 전체가 그 위에 선다. 오늘 실제로 그럴 뻔했다 —
`max_gap=3.4min` 만 보고 "수집 정상"이라고 쓸 뻔했고, DB 를 직접 안 봤으면 그렇게 됐다.

## 해야 할 일

1. **가장자리 구멍을 센다.** 창 시작~첫 관측, 마지막 관측~창 끝을 **각각 명시적으로**
   재서 보고하라. 간격 목록에 그냥 끼워 넣지 말고 **`leading_hole` / `trailing_hole` 로
   따로 이름 붙여** 출력하라 — 원인이 다르기 때문이다(가운데 구멍 = 수집기 문제,
   가장자리 구멍 = 기계가 자거나 창 경계가 잘못 잡힌 것).
2. **`max_gap` 을 이 둘을 포함한 값으로 고쳐라.** 지금 값은 "관측 사이 최대 간격"인데
   이름은 "최대 공백"처럼 읽힌다. 이름을 바꾸든 값을 바꾸든, **읽는 사람이 속지 않는 쪽**으로.
3. **결손 감사(`ops/gap_audit.py`)에도 같은 검사를 넣어라.** 거기도 같은 모양일 것이다 —
   **확인하고 결과를 보고하라**(멀쩡하면 멀쩡하다고 적어라, 고치지 말고).
4. **어느 등급으로 떨어뜨릴지 정하라.** 오늘 잠든 것은 사용자가 노트북을 닫은 것이라
   `PLANNED_` 창이 걸려 있었다(09:00 만료). 가장자리 구멍이 그 창 안이면 `PLANNED_`,
   밖이면 `ALERT_` 여야 한다. 어제 네가 만든 4등급 체계를 그대로 쓰면 된다.

## 함께 볼 것 — 오늘 아침의 실제 타임라인 (근거)

```
08:01:16  telemetry  session=after  api_errors=0  fetch=100%     <- 정상
08:01:46  마지막 랭킹 폴 (DB)
   ...    약 60분 아무것도 안 돎 (기계 수면, 배터리)
09:01:13  telemetry  session=day  ranking_snap_age_s=3566        <- 깨어나자마자 재개
09:01:36  ALERT_on_battery (charge 72%)
```

수집기 프로세스는 **죽지 않았다**(`col_up` 이 이어짐, 23:36 기동본 그대로).
기계가 잔 것이고 깨어나서 스스로 재개했다 — **§4.5 자동 복구는 제대로 동작했다.**
고칠 것은 복구가 아니라 **보고**다.

## 규율

- 가동 중 수집기 직접 접촉 금지(STOP 파일 + 워치독 경로만).
- 소유 경로(`ops/**`, `docs/11`, `docs/31`, `docs/34`)만. `tossmon/**` 은 손대지 말고 보고.
- 브랜치 `w5-ops`, pytest green, 콘솔 출력 비ASCII 금지(cp949 로 죽는다).
- **네 수정을 직접 깨보고 보고하라.** 인위적으로 창 끝이 빈 데이터를 만들어
  (a) 구멍이 보고되는지 (b) **가운데 구멍은 여전히 보고되는지** 둘 다 시험하라.
  이 프로젝트에서 "가드를 만들었다"는 보고가 실제로는 목록에 적힌 것만 검사한 사례가 세 번 있다.
- 커밋을 자주 하라 — 어제 네 태스크가 네트워크 유실로 턴째 날아갔다.
- `worker_done` 1회(ASCII), (a) 한 일 (b) 검증 방법 (c) 못 한 것 (d) 소유권 밖 발견
  (e) 다음 사람이 알아야 할 것.
