# W5 — 5일 무인 수집 하드닝 (사용자 지시: "절대 끊김 없이 양질의 데이터")

너는 W5(ops 소유자)다. 수집기는 지금 가동 중이고 월 09:00 개시 대기다. **이번 주 5일을
무인으로 버텨야 하며, 중간에 죽으면 그 구간 랭킹은 영구 소실**이다(과거 조회 불가).
지금까지 실제로 겪은 사고를 전부 막는 구조를 만들어라. **가동 중인 수집기는 건드리지
말고**(재기동이 필요하면 그 시점을 보고 후 결정), 방어층을 덧대는 방식으로.

## 핵심 요구 — 에이전트도 사람도 없이 스스로 버틸 것

이 세션(코디네이터)은 언젠가 끝난다. **감시·복구가 에이전트에 의존하면 실패**다.

1. **OS 레벨 워치독** (최우선): schtasks 로 5분마다 도는 독립 점검 스크립트.
   점검: (a) collector·supervisor 프로세스 생존 (b) 로그 신선도 (c) **개장 세션 중
   텔레메트리 카운터 전진**(동결 = API 사망 신호 — 어제 2시간 사고의 유일한 조기 신호였다)
   (d) 디스크 여유 (e) 토큰 상태. 실패 시 **자동 재기동**(백오프·재시도 상한 포함),
   그리고 `data/ALERT_<timestamp>.txt` 에 사유 기록.
   워치독 자신도 죽을 수 있으니 **워치독 부재 시 수집기 측에서 감지**하는 상호 감시 권장.
2. **디스크 방어**: 5일치 성장 추정(현재 DB 415MB/1일)과 여유(14.6GB) 대조. 임계
   (예: 3GB) 미만이면 로그 로테이션·오래된 백업 정리·경보. **Errno 28 로 죽는 일이
   다시 없게** — 쓰기 전 여유 확인 또는 저용량 모드.
3. **로그 로테이션**: 5일이면 collector.log 가 수십 MB~GB 로 큰다. 회전·압축·보존정책.
4. **전원**: 배터리 구동 시 죽지 않도록 schtasks 설정은 이미 해제했다. 추가로
   **AC 연결 상태·배터리 잔량을 워치독이 감시**해 배터리 모드 진입 시 ALERT 를 남겨라
   (사용자가 아침에 즉시 알 수 있게). 절전 진입 방지 설정도 확인·보고
   (현재 AC=안 잠, DC=4분 유휴 시 절전).
5. **재기동 내성**: 재기동 시 env(TOSS_BASE_URL 등) 누락으로 죽은 전례가 있다 —
   워치독 재기동 경로가 env 를 항상 보장하도록. 토큰 만료·재발급 실패도 워치독 점검 항목.
6. **일일 무결성 점검** (경량): 하루 1회, 전날 수집분의 랭킹 스냅 간격·봉 수·이벤트 수를
   요약해 `data/daily_health_<date>.txt` 로 남겨라. 데이터 품질이 조용히 나빠지는 것을
   사후에 알 수 있게.

## 검증

- 각 방어층을 **실제로 발동시켜 확인**하라 (프로세스 강제 종료 → 자동 복구 확인,
  디스크 임계 모의, 로그 신선도 위반 모의). 검증 없이 "만들었다"는 보고 금지.
- 검증 중 라이브 수집이 끊기면 안 된다 — 모의는 복제/샌드박스 경로로.

## 보고

`worker_done` 1회(ASCII): 각 방어층 + **어떻게 발동 검증했는지** + 남은 단일 실패점
(솔직하게) + 사용자가 아침에 확인할 파일 경로 목록. 소유 경로 밖 수정 금지, `w5-ops` 커밋.
