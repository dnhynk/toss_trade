# W5 — 유니버스 필터 적용 재수집 (라이브 리스 부여)

너는 W5(`ops/**`, `docs/08_runbook.md`, `docs/09_secret_hygiene.md`, `tools/dryrun_night.py`,
`docs/11_live_rehearsal.md` 소유자)다. **오케스트레이션 런타임이 리셋됐다** — 옛 taskId/dispatchId 는
전부 무효다. 네 재개 지점은 `coordination/HANDOFF-W5.md` 에 네가 적어뒀다. 먼저 읽어라.

## ★ 라이브 리스를 너에게 부여한다
지금 리스 보유자는 없다(어제 네가 반납했고 락 해제도 확인됐다). 너만 실서버를 호출할 수 있다.

**⚠️ 전환 규칙 (계약 A6) — 어제와 다르다.**
리스 위치가 `{state_path}.lock`(CWD 종속) → **`sha256(client_id)` 기반 리포 밖 고정 위치**
(`TOSSMON_LEASE_DIR`, 미설정 시 `LOCALAPPDATA`)로 바뀌었다. 어제 감사가 찾은 치명 결함
(워크트리마다 다른 락을 잡아 두 프로세스가 동시에 토큰 발급)의 수정이다.
- 구코드 프로세스가 **완전히 종료됐는지** 먼저 확인하라(어제 것은 종료 확인됨).
- 신코드로만 띄워라. 구/신 코드가 동시에 라이브면 **여전히 상호 토큰 살해가 난다.**

## 배경 — 왜 재수집인가
어제 밤 15시간 수집은 **파이프라인이 무인으로 도는가**를 검증했고 그건 성공했다
(세션 전환 4회, api_errors=0, 재시작 이어받기 3회).
그러나 적대적 감사가 밝혔듯 **유니버스 필터가 수집 경로에 한 번도 적용되지 않아**
NOK·AMD·ASML·META 같은 대형주가 워치리스트를 채웠고, tier2 를 차지해 **tier3 진입을 봉쇄**했다.
즉 어제 데이터는 **표적 모집단이 아니다.** W4 가 이를 고쳤고 main 에 머지됐다.
이번 수집은 **분석에 쓸 수 있는 첫 데이터**를 만드는 것이 목적이다.

## 절차

### 1. 준비
- `git rebase main` (main 은 감사수정 전부 + 유니버스 게이트 머지됨, **704 tests green**)
- `.venv\Scripts\python -m pytest -q` 로 통과 확인
- `config/config.yaml` 준비 (`config.example.yaml` 복사 → `api.live: true`,
  `base_url: https://openapi.tossinvest.com`). **커밋 금지.**
- **DB 는 새로 시작하라.** 어제 DB(`data/tossmon.db`)는 오염된 모집단이므로 섞지 마라.
  기존 파일은 `data/tossmon_20260730_polluted.db` 같은 이름으로 **보존**하되(삭제 금지 —
  파이프라인 검증 증거이자 W5 리포트의 근거다), 새 수집은 새 DB 로 한다.

### 2. 유니버스 빌드 (수집보다 먼저)
```
python -m tossmon.universe --config config/config.yaml
```
W2 가 만든 진입점이다. `/stocks` 배치 + 일봉으로 tier0/tier1 을 산출해 `symbols` 테이블에 넣는다.

★ **결과를 반드시 검증하고 기록하라** — 이게 이번 태스크의 핵심 검증이다:
- **tier0/tier1 통과 종목 수.** 너무 적으면(예: 수십 개) 필터가 과하게 좁은 것이고,
  너무 많으면(수천 개) 필터가 사실상 안 걸린 것이다. 숫자를 보고 판단해 보고하라.
- **통과 종목의 가격·시총 분포** — 실제로 $0.1~$20 / $10M~$300M 안에 있는지 표본 확인.
- **어제 오염 사례가 걸러지는지 직접 확인**: NOK·AMD·ASML·META·GS 가 `symbols` 에
  없거나 tier0 미통과인지. **이 5종목 이름을 명시적으로 조회해 결과를 리포트에 적어라.**
- 외부 심볼 디렉토리 수집이 네트워크에 의존한다 — 실패하면 캐시 폴백이 도는지 확인.

### 3. 수집 시작
```
python -m tossmon.collector --config config/config.yaml
```
- **반드시 `Start-Process` 분리 프로세스로** 띄워라 (어제 배운 것: 에이전트 세션의
  백그라운드 잡으로 띄우면 세션 정리 때 함께 죽는다).
- `ops/supervisor.py` 로 감시하되 supervisor 자체도 분리 프로세스로.
- 지금 KST 13:2x — **데이마켓(09:00~17:00) 진행 중**이다. 이어서 프리(17:00)·정규장(22:30)이 온다.
  세션 전환을 그대로 관측하게 된다.

### 4. 시작 직후 30분 내 검증 (여기가 진짜 확인 지점)
- **워치리스트에 대형주가 들어오지 않는지** 로그로 확인하라. W4 가 거부를 로그·카운터·
  텔레메트리로 노출하게 만들었다. 거부 건수가 실제로 올라가는지 보라.
- **tier2/tier3 점유가 어제와 어떻게 다른지.** 어제는 tier3 피크가 4/20 이었다.
  대형주가 빠졌으니 표적 종목이 tier3 에 올라와야 정상이다. **안 올라오면 그것도 발견이다**
  (필터가 과하게 좁아 감시 대상이 없는 것일 수 있다).
- 예산 실측: 어제는 tier3 미만석으로 MARKET_DATA 0.03~1.27/7.00 이었다. 이번엔 어떤지.
- **`ForbiddenEndpoint` 관련 주의**: W4 가 지금 그 예외 처리를 고치는 중이다(미머지).
  만약 수집 중 allowlist 위반이 발생하면 **미처리 예외로 루프가 죽는다.** 정상 동작에서는
  발생하지 않지만, 프로세스가 조용히 사라지면 이것부터 의심하고 즉시 보고하라.

### 5. 보고
- 시작 후 **30분 시점에 status 로 중간 보고** (위 §4 항목).
- 이후는 어제처럼 무인 운영하고, 세션 종료 시 `tools/dryrun_night.py` 로 최종 리포트.
- 어제 리포트와 **나란히 비교**할 수 있게 같은 지표를 내라 — 유니버스 필터의 효과가
  숫자로 드러나야 한다(워치 구성, tier 점유, 이벤트 수, 승격 사유 분포, churn).

## 불변 규칙
1. 리스 보유자는 너 하나다. 다른 워커는 전부 mock 전용이다.
2. `api_keys` 내용을 출력·로그·커밋·메시지에 절대 넣지 마라.
3. 소유 경로 밖 수정 금지. `config/config.yaml`·`ops/ops_config.yaml`·DB 는 커밋 금지.
4. `main` 직접 커밋 금지. 자기 브랜치에만.
5. **거래 코드 금지** — 주문/조건주문/계좌변경을 어떤 형태로도 호출하지 않는다.
6. 설계 전제를 깨는 발견이면 자체 판단 말고 즉시 escalate.
   특히 **필터 통과 종목이 극단적으로 적거나 tier3 가 여전히 비면** 그건 설계 재검토 사유다.
7. `worker_done` 은 세션 종료·최종 리포트 후 1회. 중간 보고는 `status`.
