# W4 후속 — 이벤트 재검출 중복 억제 + 알림 소음 (라이브에서 발견)

너는 W4(`tossmon/collector/**`, `tossmon/config.py` 소유자)다. 짧은 후속 1건. **mock 전용**.

## 문제 (라이브 수집 중 코디네이터가 직접 관측)
검출기가 **매 사이클 버퍼를 다시 스캔하며 같은 이벤트를 재검출**한다.
실측: 7분에 events 15행 / 고유 (symbol,t0_ms) 9개 — 40% 중복.
로그도 같은 이벤트가 반복해서 `ERROR EVENT ...` 로 찍힌다.

DB 레벨 중복 방지(UNIQUE + UPSERT)는 W2 에 별도 지시했다. **네 쪽 작업은 두 가지다:**

1. **재검출 억제**: 이미 기록한 (symbol, t0_ms) 는 다시 `record_event` 하지 않도록
   in-memory 집합으로 억제하라. 단 **완전 차단은 하지 마라** — T0 시점에는 peak_ms·
   peak_ret·ret_close 가 미확정이고 장이 진행되며 채워지므로, **라벨이 실제로 바뀌었을 때는
   갱신 목적으로 다시 보내야 한다.** 권장: (symbol,t0_ms) → 마지막으로 보낸 라벨 해시를 들고
   있다가 **해시가 바뀔 때만** 재기록. 그러면 DB UPSERT 와 맞물려 라벨이 최신으로 유지되면서
   불필요한 쓰기와 로그는 사라진다.
2. **알림 소음**: `notifier.event` 가 `alert`(ERROR) 로 나가는데, **같은 이벤트의 반복 알림**과
   **과거 세션 백필로 뒤늦게 검출된 이벤트**까지 전부 ERROR 로 찍혀 알림 채널이 오염된다.
   실측 로그에서 `session=day` 인 과거 이벤트가 프리마켓 수집 중에 ERROR 로 올라왔다.
   → **최초 검출 1회만 alert**, 이후 라벨 갱신은 `info` 로. 그리고 **현재 세션이 아닌
   과거 시각(t0_ms 가 현재 세션 시작 이전)의 이벤트는 alert 가 아니라 info** 로 내려라.
   무인 야간 운영에서 alert 는 "사람이 반드시 봐야 하는 것"만 남아야 의미가 있다.

## 재시작 고려
오늘 밤 23:30~00:30 에 프로브를 위해 collector 를 계획 정지·재기동한다.
**in-memory 억제 집합은 재시작 시 비므로 재기동 직후 한 번은 다시 기록될 수 있다.**
그건 DB UPSERT 가 흡수하므로 문제 없다 — 다만 재기동 직후 alert 폭주가 없도록
**기동 시점에는 과거 이벤트를 alert 하지 않는 규칙**이 확실히 걸리게 하라.
