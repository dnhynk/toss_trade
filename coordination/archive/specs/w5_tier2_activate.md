# W5 — 티어2 호가 활성화 + 재기동 (추적용 정식 태스크)

너는 W5 다. 이 내용은 이미 터미널로 전달했으나 **추적 태스크 없이 보낸 코디네이터 실수**라
정식 태스크로 재발행한다. 경보 파일 재분류(마지막 항목)는 이미 끝냈으니 **나머지를 완료**하라.

**현재 실측(코디네이터)**: 최근 30분 호가 3종목 255건 = 여전히 tier3 뿐. 티어2 미활성.

## 작업

1. `git rebase` w5-ops onto main (main = `4e6e24b`, 995 green — W4 의 티어2 코드 포함).
2. **라이브 `config/config.yaml`** 의 `polling:` 아래에 **`tier2_orderbook_s: 600`** 추가.
   (이 파일은 gitignore 라 W4 가 커밋할 수 없었다. 600 은 W4 의 예산 근거값 —
   MARKET_DATA 여유 0.572 req/s, 티어2 최대 부하 시에도 0.500 이라 안전. 300 은 초과.)
3. **검증된 STOP 파일 + 워치독 자동복구 경로**로 재기동(약 61초 공백).
   **직접 프로세스를 띄우지 마라.** 재기동은 계획 정비이므로 네가 새로 만든 마커 방식으로
   기록해 ALERT 오탐을 남기지 마라.
4. **재기동 후 실증**: tier2 심볼(= tier3 아닌 종목)의 호가 행이 실제로 쌓이는지 확인하고
   **종목 수·행 수를 보고**하라. tier3 폴링 주기가 영향받지 않았는지도 확인.
   활성화됐는데 안 쌓이면 그 사실을 escalation.
5. **워치독에 신규 카운터 2종 배선**: `tier2_orderbook_snaps`(세션 열림인데 평평 = 미수집,
   WARN), `tier2_orderbook_skipped`(증가 = 예산 압박 양보, INFO).

## 보고

`worker_done` 1회(ASCII) — 선택한 설정값, 재기동 시각·공백, **티어2 호가 실증 수치**,
워치독 배선 결과. 이후 다시 무인 감시로 복귀(에이전트 폴링 금지).

## 불변 규칙

소유 경로 밖 수정 금지(`config/config.yaml` 은 라이브 운영 파일이라 예외 — 커밋 대상 아님),
`w5-ops` 커밋, main 금지. 가동 중 수집기는 STOP 파일 경로로만 다뤄라.
