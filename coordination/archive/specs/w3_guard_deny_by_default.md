= W3 — 가드에 구멍이 있다: **허용 목록이라 잊은 것은 검사되지 않는다**

배선은 완벽하다. 세 표가 `main()` 에서 나오고 `[docs/23 sec 10-N.8]` 태그로 문서와
줄 단위 대조가 된다. 내가 직접 돌려 12/12 `crosses_zero` 를 재현했고, `out/` 분리와
`.gitignore` 정리도 확인했다. 페이퍼 트레이딩 정정을 문서에 남긴 것도 옳다.

**그런데 가드를 시험해 보니 통과시켰다.**

## 내가 한 시험 (재현 가능)

`design_b.py` 끝에 **`main()` 에서 도달 불가능한 분석 함수**를 하나 심었다:

```python
def sharpe_by_rule(df, rule):
    """새 분석 - 문서에 실었지만 배선을 잊었다."""
    v = df[rule]
    return float(v.mean() / (v.std() or 1.0))
```

결과: **`tests/test_design_b_wiring.py` 16개 전부 통과.**
이것은 네가 막으려던 바로 그 상황이다 — 새 분석을 추가하고 배선을 잊은 상태.

## 원인

```python
MUST_BE_REACHABLE = ("run", "build_report", ..., "summarize", "exit_rules")
```

**허용 목록(allowlist)이다.** 여기 적힌 함수만 도달성을 검사한다.
그런데 **"목록에 적는 것"과 "배선하는 것"은 같은 순간에 잊는다.** 다음 사람이 함수를
추가하고 목록에 안 적으면 가드는 **질문조차 받지 않는다.** 통과가 보증이 아니다.

`REPORTED_FIELDS` 도 같은 모양이다 — 문서에 열을 추가하고 매니페스트에 안 적으면 조용하다.

## 고칠 것 — **거부 기본값(deny by default)** 으로 뒤집어라

1. 목록을 **열거하지 말고 발견하라**: 모듈의 **공개 함수 전부**(`_` 로 시작하지 않는)를
   AST 로 수집해 **각각 `main()` 에서 도달 가능해야 한다**로 바꿔라.
2. 예외는 **명시적 옵트아웃 + 사유**로만 허용하라:
   ```python
   NOT_WIRED = {
       "main": "진입점 자신",
       "ro":   "커넥션 헬퍼 - 산출물 없음",
   }
   ```
   목록에 없는 새 공개 함수가 도달 불가능하면 **테스트가 실패**한다.
   그러면 다음 사람은 **배선하거나, 사유를 적거나** 둘 중 하나를 반드시 하게 된다.
3. `REPORTED_FIELDS` 도 같은 방향으로: 러너 JSON 의 규칙 레코드 **키 집합과 매니페스트가
   정확히 일치**해야 한다(부분집합이 아니라 **동일**). 키를 추가하고 매니페스트를 잊으면 실패.
4. **가드 자신을 시험하는 테스트를 넣어라.** 위의 `sharpe_by_rule` 같은 더미를
   임시 소스에 심어 **가드가 실패하는 것을 확인**하는 테스트다(소스 문자열을 만들어
   AST 검사 함수에 직접 넣으면 파일을 건드릴 필요 없다).
   **가드가 실패할 수 있음을 증명하지 못한 가드는 가드가 아니다.**

## 왜 이걸 크게 다루는가

이 프로젝트에서 같은 모양이 세 번 나왔다:
- 룩어헤드 테스트 14건이 **죽은 설계만** 지켰다(감사5 H-2) — 산 설계는 질문을 안 받았다.
- `paired_difference` 가 **테스트에서만** 불렸다(H-1 재발) — 산출물은 아무도 안 만들었다.
- 이번 가드가 **목록에 적힌 것만** 검사한다 — 잊은 것은 검사되지 않는다.

전부 **"성공을 반환하는 조용한 실패"** 다. 통과했다는 사실이 아무것도 보증하지 않는다.
네가 (d)에서 `summarize` 가 도달 불가능해진 것을 가드가 잡았다고 했는데, 그건
`summarize` 가 **이미 목록에 있었기 때문**이다. 목록 밖은 여전히 사각지대다.
