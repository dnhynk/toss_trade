= W1 — `amount_u` 필드 의미 확정 (계약 위반 의혹, 분석 결과에 직결)

너는 W1(`tossmon/api/**`, `docs/06_live_facts.md` 소유자)이다. **C4 작업을 마친 뒤** 이걸 하라.

## 발견 (W3, docs/23)

`rankings_snap.amount_u` 를 금액으로 쓰면 안 될 정황:
- **누적이 아니다** (코디네이터·W3 둘 다 누적으로 오인해 쓴 적 있음)
- `vol_qu × last_u` 에서 **상수 1.44e9 로 완전히 유도된다**
- **1.44e9 = 1e6 × 1440** 이고 1440 은 USD/KRW 환율 수준 → **원화 표기 의심**
- 그렇다면 `docs/04` 의 "KRW 는 등장하지 않는다(US 전용)" 계약과 **충돌**

이는 감사 3차가 잡은 `vol_qu/10000` 오류와 같은 계열(단위 오해)이며,
**코디네이터가 사용자에게 보고한 "12초 흐름 $432k" 수치도 이 필드에 기반**했다.

## 작업

1. 실제 API 응답(픽스처·mock·docs/06 실측 기록)으로 `amount` 계열 필드의 **단위와 통화**를
   확정하라. 필요하면 여러 종목·세션의 저장분을 대조해 `vol_qu × last_u` 유도 관계를 검증.
2. **결론을 `docs/06_live_facts.md` 에 명시**하라 — 단위, 통화, 누적/구간 여부, 그리고
   "금액 지표로 써도 되는가".
3. 계약(`docs/04`)과 충돌하면 **고치지 말고** (c)에 계약 개정 요청으로 올려라(그 문서는
   코디네이터 소유).
4. 파서·모델에 단위가 드러나는 이름이나 주석이 필요하면 네 소유 경로 안에서 반영하고
   회귀 테스트를 붙여라(예: 컬럼명에 단위를 박은 W3 의 `amount_u12` 관행 참고).
