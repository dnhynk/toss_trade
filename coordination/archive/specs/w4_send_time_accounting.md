# W4 — 예산 계상을 완료 시각에서 송신 시각으로 (docs/45 §7 "근본" 항목)

## 왜 지금인가 — 조건이 발화했다

§4.13(08-09)이 **미리** 정한 관측 규칙이 있었다:

> `md_peak_1s` 가 계속 11~13 이면 다음 수정은 송신시각 계상이다.
> 판단 시점은 **월요일 개장(22:30 KST)**.

**08-10 정규장 개장 실측 (코디네이터가 `collector.log` 에서 직접 읽음):**

```
22:30:02 regular  md_peak_1s=10  p95=7.0
22:35:03 regular  md_peak_1s=12  p95=8.0
22:40:03 regular  md_peak_1s=12  p95=9.0
22:45:03 regular  md_peak_1s=11  p95=8.0
22:50:04 regular  md_peak_1s=11  p95=9.0
22:55:04 regular  md_peak_1s=10  p95=9.0
23:00:05 regular  md_peak_1s=12  p95=8.0
```

**한도 10 을 계속 넘는다. 조건 발화.** 08-08 배포로 D1(클램프 없는 전역 시도 델타)과
D2(`max(booked, max(1,calls))` 바닥값)는 닫혔는데도 잔여가 남았다 — W4 가 예고한 그것이다.

## 무엇을 고치는가

`docs/45` §7 항목 3(근본):

> 계상 시각을 **완료 시각이 아니라 송신 시각**으로. 리미터가 이미 진짜 송신 시각을
> `_Bucket.sent` 에 갖고 있다(`snapshot()["window_used"]`). 예산이 그것을 읽으면
> D1·D2·완료시각 문제가 **한꺼번에** 사라진다 — 그게 원인을 설명하는 수정이다.

**코디네이터 실측**: `window_used` 는 `budget.py`·`loops.py` 어디에서도 읽히지 않는다
(grep 0건). 배선 자체가 없다. 즉 이 항목은 아직 손도 안 댄 상태다.

> **정정 — 상태 문서의 인용이 틀렸다.** §4.13 은 이 후속을 "W1 / `limiter.py`" 로 적었다.
> `docs/45` §7 원문은 **"원인은 `budget.py` 와 `loops.py` 의 계상 경로에 있다. 둘 다 W4 소유"**
> 이고, 리미터는 **고칠 대상이 아니라 읽을 대상**이다(§2 에서 구조적으로 무죄가 증명됨).
> 소유자와 파일 둘 다 정정해 이 태스크를 낸다.

## 같이 처리할 부수 발견 — 수명이 다른 카운터가 나란히 찍힌다

오늘 코디네이터가 잰 것:

| 카운터 | 출처 | 수명 |
|---|---|---|
| `http_429` | `client.counters` (`loops.py:905`) | **클라이언트** — 재생성마다 0 |
| `http_429_under_own_limit` | `self.counters` (`loops.py:902`) | **수집기** — 안 리셋됨 |

그래서 같은 텔레메트리 한 줄에 `under_own_limit=391 > http_429=138` 이라는
**불가능해 보이는 조합**이 찍힌다. 실제로는 분모가 다른 두 값이다.

이것이 실제로 운영 판단을 오염시켰다: §4.12 는 **"`http_429` 가 0 을 유지하면 급하지 않다"**
는 규칙을 세웠는데, 그때 본 0 은 **재시작 15분 뒤 값**이었다. 재시작 **직전** 값은 3 이었고,
현재 인카네이션(73시간, 재기동 0회)에서는 **단조 증가해 172** 다.

→ **수명이 다른 값을 나란히 찍지 마라.** 카운터마다 수명을 텔레메트리에 명시하든,
같은 수명으로 통일하든 하나를 골라 근거와 함께 보고하라.

## 해야 할 것

1. **먼저 실패를 재현하는 테스트를 써라** (이 프로젝트 규율). 완료 시각 계상이 첨두를
   부풀린다는 것을 결정론적으로 보이는 테스트. 고치기 전에 red 여야 한다.
2. 예산이 `limiter.snapshot()["window_used"]` 를 읽도록 배선하라. D1·D2 클램프가
   불필요해지면 지우되 **지운다는 사실과 근거를 보고**하라 — 조용히 지우지 마라.
3. **가드를 직접 깨서 확인하라.** D1·D2 재발 방지 테스트가 지금도 red 를 낼 수 있는가?
   (이 프로젝트는 "허용 목록만 검사하는 가드"에 이미 한 번 뚫렸다.)
4. 카운터 수명 표기.
5. **예상 효과를 숫자로**: 같은 로그 구간에서 옛 계상 vs 새 계상의 `md_peak_1s` 분포를
   오프라인으로 재계산해 대조표를 내라.

## 금지 (어기면 태스크 실패로 본다)

- **수집기 재시작·배포 금지.** 배포는 공백을 만들고 사용자 승인 사항이다.
- **라이브 API 호출 금지.** 이 판정에 라이브는 필요 없다 — `docs/45` 가 라이브 0건으로 냈다.
- **`limiter.py` 수정 금지.** 읽기만 하라.
- **폴 주기 변경 금지.** §4.12-5 는 사용자 결정 대기 중이다.
- **판정 금지**: "이제 한도 안이다" 를 배포 전에 선언하지 마라. 오프라인 재계상 결과만 보고하라.
