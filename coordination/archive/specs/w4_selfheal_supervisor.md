# W4 — 백필 자가 복구 슈퍼바이저 (사용자 지시: "중단돼도 개입 없이 빠르게 되살아나게")

너는 W4 다. 오늘 백필이 두 번 죽었다 — 둘 다 **사람이 몇 시간 뒤에 발견**했고, 둘 다
기계적으로 복구 가능한 유형이었다(403 IP 플랩은 IP 가 저절로 돌아왔고, 체크포인트는
멱등이다). 사용자 지시로 이를 구조적으로 끝낸다. **현재 돌고 있는 재개 런은 건드리지
말고**, 병행으로 만들어서 다음 기동(네트워크 단절 후 재개)부터 이걸로 돌린다.

## 요구 — `tools/backfill_supervisor.py` (+ `tests/test_backfill_supervisor*.py` 소유권 부여)

1. **감시-재기동 루프**: 백필 러너를 자식으로 띄우고 종료를 감시한다.
   - 정상 완료(계획 소진) → 매니페스트 확인 후 종료.
   - **403 ip-not-allowed 로 죽으면**: 10분 간격으로 값싼 프로브(캘린더 1콜)를 반복,
     성공하는 순간 체크포인트에서 자동 재개. 상한 없음(사용자가 포털 등록을 마치면
     그 즉시 저절로 살아난다) — 단 매 시간 로그에 대기 사실을 명시.
   - 기타 일시 오류(네트워크·5xx·프로세스 외부 킬) → 백오프(1/5/15분) 재기동.
   - **같은 지점에서 3회 연속 크래시** → 재시도 중단, 로그에 `ESCALATION:` 줄
     (코디네이터 감시가 이 문자열을 잡는다), 오케스트레이션 escalation 도 시도.
2. **정직한 텔레메트리**: STATUS 방출을 슈퍼바이저에 내장 — 30분마다
   체크포인트 실측 + **러너 생존 여부**를 함께 찍는다. 러너가 죽어 있으면
   `RUNNER-DEAD`(재기동 대기 중이면 그 사유·다음 시도 시각) 를 찍는다.
   오늘처럼 죽은 숫자를 산 것처럼 찍는 일이 불가능한 구조로.
3. **내구 기동**: 슈퍼바이저 자체를 schtasks(현재 사용자 계정)로 띄우는 등록
   스크립트/명령 포함 — PTY 리퍼·콘솔 처닝과 무관하게 생존해야 한다.
4. **우아한 정지**: STOP 파일(경로를 로그 첫 줄에 명시) → 러너에 정상 정지 전달 →
   체크포인트 플러시 확인 후 종료. `--deadline "YYYY-MM-DD HH:MM"` 인자로
   자체 정지 시각도 받게 하라(분할 실행·네트워크 컷 대응).
5. **검증은 mock 으로**: 오늘 밤 라이브 재검증 금지(러닝 중인 실행과 경합 금지).
   러너를 가짜 스크립트로 치환해 시나리오 테스트 — 403 죽음→프로브 대기→재개,
   외부 킬→백오프 재개, 3연속 크래시→ESCALATION, STOP/deadline 정지, STATUS 정직성.
   전체 pytest green.

## 불변 규칙

1. 진행 중인 백필 런·그 체크포인트/DB 에 간섭 금지. 라이브 호출 금지(mock 검증만).
2. 소유 경로(기존 + 신규 2파일) 밖 수정 금지. `w4-collector` 에만 커밋, main 금지.
3. `worker_done` 1회(본문 ASCII), (a)~(e) — (e)에 **다음 재개 때 슈퍼바이저로 기동하는
   정확한 명령**을 적어라.
