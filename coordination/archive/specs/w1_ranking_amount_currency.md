## 해야 할 일

1. **가설을 확정하거나 기각하라.** 라이브 호출 없이 `docs/01_api_analysis.md`·
   `docs/06_live_facts.md`·응답 픽스처·파서(`tossmon/api/**`)로 확인 가능해야 한다.
   원본 응답에 통화 필드나 별도 금액 필드가 있는지 봐라.
   **확정 못 하면 "확정 못 했다"고 보고하라** — 추측으로 숫자를 바꾸지 마라.
2. **사실이면 `docs/06_live_facts.md` 에 실측 사실로 기록하라.** 이게 이 태스크의 핵심이다.
   지금 `_u` 접미사가 붙은 다른 컬럼(`last_u`·`price_u`·`close_u`·`open_u`·`high_u`·`low_u`)은
   **전부 USD 마이크로**다. `amount_u` 만 이름이 같고 통화가 다르면
   **다음 사람이 `amount_u/1e6` 을 달러라고 부르는 순간 1,433배 틀린다.**
3. **지금 쓰는 곳 2군데는 안전하다 — 코디네이터가 확인했다. 다시 확인만 하고 건드리지 마라:**
   - `analysis/features.py:507-512` `toss_share = toss.amount_u / mkt.amount_u`
     — 같은 스냅샷의 비율이라 **환율이 정확히 상쇄된다.**
   - `analysis/measure/rotation_pilot.py:59` — 상위 N 선별·순서에만 쓰므로
     **단조 변환이라 순서가 보존된다.**
   - `analysis/rotation.py` 는 `amount_u12 = close_u × vol_qu` 로 **직접 다시 계산**하고
     `amount_usd()` 를 통과시킨다 — 이미 올바른 경로다(감사 4차 B10).
4. **재발 방지**: 절대 금액으로 쓰면 걸리는 가드를 제안하라(강제는 하지 마라).
   컬럼 이름 변경은 **저장 스키마 변경이라 이 태스크 범위 밖**이다 — 권고만 적어라.
5. **클램프 자체는 정직하게 동작했다** — 값을 저장하고, 카운터를 올리고, 경고를 찍었다.
   **조용히 버리지 않았다.** 이 설계는 그대로 두라고 보고에 적어라.
   다만 클램프된 행을 분석에서 골라낼 방법이 **"`amount_u` == int64 max" 뿐**이다.
   그것으로 충분한지 판단해 보고하라.
