## 3-1. 확정된 결정 — 다시 열지 마라

| 결정 | 이유 |
|---|---|
| **예산의 사건 타임라인만 monotonic 으로 분리** | 서버 오프셋이 초 해상도 헤더에서 나와 ±180ms 출렁이는데 송신 간격이 118~157ms 라, 한 번 눌릴 때마다 여러 송신이 같은 순간으로 압축됐다. **첨두 11~13 은 실재가 아니었다** |
| 워밍업·쿨다운·지속·429 회복은 **벽시계 유지** | 세션 경계가 서버 시각으로 정의된다 |
| **계획 표식을 창이 아니라 키가 덮게** | 표식 하나가 2 시간짜리 워치독 사망을 `PLANNED_` 로 삼켰다. 수집 부재 키 18 개만 덮고 나머지 39 개는 계획 창에도 `ALERT_` |
| **침묵한 감시점 셋을 서버 `date` 초로 재조준** | 송신시각 계상 아래서 그 셋은 **구조적으로 발화 불가**가 됐다. *"조용하다"를 "안전하다"로 읽으면 안 된다* |
| **한 번에 하나만 배포** | 08-12 밤 정규장에 시계 수정만 넣었다. 그 덕에 **73.1%→0.0% 이 오롯이 시계의 것** |
| **천장 유지 + 클램프 로깅만** (사용자) | 지금 5/s 도 다 안 쓴다(avg 0.60). **두 번째 리미터 정체를 모른 채 천장을 4 배로 올리면 그것을 더 세게 때린다** |
| 클램프 카운터의 **방향을 가른다** | `clamped`(위로 잘림=기회 손실)와 `lowered`(정상 하향)를 한 통에 세면 이 관측이 또 묻힌다 |
| **`docs/07` §4.1 의 `≥ 1` 문언을 지우지 않음** | `strict_lt` 에서는 참이다. 두 모드를 나란히 적고 **섞지 말라**고 박았다 |

## 5. 운영 규율 (구속력 있음)

### 5-1. 무인 장기 실행 표준 (2026-08-02 사용자 지시)

**"중단돼도 사용자 개입 없이 빠르게 복구"가 모든 무인 장기 실행의 기본 요건이다.**
백필 2 연속 사망(PTY 킬 8 분 공백, IP 플랩 5 시간 미발견)에서 채택. 3 층 구조:

1. **자가 복구 슈퍼바이저** — 403 은 10 분 프로브 대기 후 자동 재개(IP 플랩 자가 치유),
   일시 오류 백오프 재기동, 3 연속 크래시만 ESCALATION. STATUS 는 러너 생존을 함께
   찍는다(**죽은 숫자 위장 불가**). schtasks 기동 + STOP 파일 + `--deadline`.
2. **코디네이터 독립 감시** — 로그 기반 Monitor(FATAL/RUNNER-DEAD/ESCALATION + 40 분 침묵).
   워커 전멸에도 작동한다. **새 코디네이터는 인수 시 재무장할 것.**
3. **사용자 개입은 진짜 필요한 것만** — 현재 유일: 토스 포털 IP 등록(자동화 불가).

### 5-2. 여섯 개는 2026-08-04 하루에 배웠다 (워커가 세 번 잡았다)

**`dispatched` 는 "보냈다"이지 "받았다"가 아니다 — 하트비트를 봐라.**
이날 네 번 당했다(하루 걸린 게이트, 에이전트 없는 터미널, 턴 끝난 뒤의 우편함,
**13 시간 `dispatched` 에 하트비트 0**).
```bash
orca orchestration dispatch-show --task <id> --json    # last_heartbeat_at
```
`last_heartbeat_at: None` 이면 **아무도 안 하고 있다.** 상태값만 보고 "진행 중"이라 하지 마라.
복구: `worker-abandon --dispatch <id>` → `task-update --status ready` → `worker-start`.

**병합했다고 말하기 전에 내용으로 확인해라.**
`git merge w1-core-api` 를 쳤는데 실제 브랜치는 `feat/core-api` 였다. Git 은
`not something we can merge` 를 냈지만 배경 출력에서 스크롤로 지나갔고 **안 바뀐 HEAD
줄을 성공으로 읽었다.** 워커가 저장소를 직접 확인해 잡아냈다 — 내 명세가 "머지 완료"라고
단언했는데도 확인한 것이 옳았다. → **`git log` 한 줄이 아니라 바뀐 파일의 내용을 grep 하라.**

**수집기 재시작을 내 세션에서 띄우지 마라.**
`schtasks /run` 을 내 셸에서 실행하면 콘솔 정리가 **Ctrl+C 를 전파**한다
(`LastTaskResult=3221225786`, 두 번 죽었다). 직접 실행은 멀쩡하므로 **예약작업 경로만** 죽는다.
안전한 절차: `STOP` 생성 → **정지를 파일이 아니라 데이터로 확인** → `STOP` 제거 →
**워치독이 5 분 주기에 되살리게 둔다.** 계획 정지에는 `data/ops_state/PLANNED` 를 함께 놓는다.

**같은 파일을 건드리는 태스크를 같은 워크트리에 겹쳐 보내지 마라.**
W4 워커 둘이 `loops.py` 를 동시에 편집할 뻔했다(한 명이 멈춰 물어봐서 막혔다).

**판정하지 말고 숫자를 가져와라.** (2026-08-04 사용자 지시)
> *"중요한 안건에 대해서는 함부로 판단하지 말고 나의 신경망으로 토론할 것."*

근거: **초 단위 전략을 1 분봉으로 분석하고 후보 6 개를 닫았다.**
워커 명세에 **"판정 금지"를 명시**하고 결론에 **측정 조건**(창 길이·판정 방법·오차율·표본
수)을 붙이게 한다. *"성립 안 함"* 이 아니라 *"N 초 창, 오차 X% 에서 관측 안 됨"*.

**"평균으로 뭉개면 안 보인다" — 분석과 인프라에서 같은 모양이었다.**
분석에서는 1 분봉 한 칸이 **6 초짜리 슈팅**을 삼켰고, 인프라에서는 60 초 평균
0.178 req/s 가 **한 초에 한도의 80%** 를 쓰는 버스트를 숨겼다.
→ 새 지표를 만들 때 **사건의 시간축과 측정 창을 먼저 대조**한다.

### 5-3. 그 밖에 비싸게 배운 것

- **워커 주장을 믿지 말고 게이트를 직접 재실행하라.** *"전체 통과"* 보고가 실제로는
  환경 문제로 일부 미실행이었던 적이 있다.
- **소유권 검증은 `git diff main..branch` 가 아니라 merge-base 기준.** main 이 앞서면 오탐.
- **idle 워커는 오케스트레이션 메시지를 안 읽는다.** 긴급 지시는 `orca terminal send`.
- **`git checkout <ref> -- <path>` 는 인덱스에 스테이징까지 한다** — 워커에게 안내할 때
  `git reset` 으로 언스테이지하라고 함께 알려라.
- **콘솔 출력에 비 ASCII 금지.** Windows cp949 에서 `UnicodeEncodeError` 로 죽는다.
  실제로 supervisor 가 이것 때문에 STOP 직후 죽어 collector 가 고아로 남을 뻔했다.
  (파이썬 일회성 스크립트도 `PYTHONIOENCODING=utf-8` 없이 돌리면 같은 이유로 죽는다.)
- **무인 프로세스를 에이전트 세션의 자식으로 띄우지 마라.** `Start-Process` 분리로는
  **부족하다** — Orca PTY job object 가 트리째 죽인다(7/31 18:07, 수집기 8 분 공백).
  **반드시 작업 스케줄러로 띄워 부모가 svchost(Schedule) 이 되게 하라.**
- **에이전트 턴이 Monitor 대기로 열려 있으면 `terminal send` 프롬프트가 큐에 갇힌다.**
  ESC 를 보내면 큐가 소비되지만 **긴 텍스트가 잘릴 수 있다**(실제로 잘렸다).
- **환경이 바뀌면 우회 수단을 굳히지 말고 원래 방식을 재시험하라** (§0 의 `check --wait` 사례).
- **codex 워커가 지출 한도에 걸리면 증액 요청하지 말고 claude 로 교체.**
